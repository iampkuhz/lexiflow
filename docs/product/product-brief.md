# LexiFlow 产品说明

> 来源：项目发起人于 2026-09-16 提供的初始需求；后续已接受 OpenSpec/ADR 若与本页冲突，以较新的显式决策为准。

<a id="problem"></a>

## 问题

传统整句中英双语字幕会遮挡英文、增加阅读切换，并且无法区分用户已经掌握与真正需要帮助的内容。词典最高频释义又经常忽略当前专业领域和上下文。

LexiFlow 要在英文内容上提供一层低打扰帮助：保留英文，只在用户可能不熟悉的核心单词、短语、术语旁给出简短、语境化的中文提示。

示例：

```text
This could materially impair（实质性损害） settlement finality（结算最终性）.
```

<a id="product-goals"></a>

## 产品目标

- 英文字幕始终是主内容，提示注释不能阻塞观看。
- 系统结合用户、内容、上下文和个人词汇档案决定提示哪些词段以及提示深度。
- 多设备、多个浏览器实例共享同一服务端个人词汇档案。
- 行为事实驱动可解释、可重算的学习状态，而不是只有 known/unknown。
- YouTube 作为首个内容适配器；网页、PDF、播客与其他视频平台可复用核心域。
- 语义供应商可替换，不把业务绑定到一家模型 API。

<a id="product-non-goals-for-the-first-release"></a>

## 首版非目标

- 整句双语字幕或每句完整翻译。
- 概率模型、向量数据库、Kafka、Kubernetes、服务网格或大规模微服务。
- PDF、播客、网页和其他视频平台的产品实现。
- 完整复习系统、内容推荐或社交能力。

<a id="first-mvp-boundary"></a>

## 首个最小可用版本边界

- Chrome 扩展 + 有英文字幕的普通 YouTube 点播视频。
- 单词、短语、专业术语三类提示注释。
- 一个账户跨多个 Chrome 实例同步。
- 一个真实语义供应商和确定性模拟实现。
- 规则型熟悉度，以及显式 known/unknown。
- 浏览器 L1、Redis L2、PostgreSQL 事实存储。
- 模型、工作进程、Redis 或后端失败时，英文观看仍可继续。

<a id="product-evidence-to-establish"></a>

## 待建立的产品证据

- YouTube 字幕在人工/自动字幕、长视频、直播回放等样本中的获取稳定性。
- 当前句和有限前后文是否足以支持高质量消歧。
- 提示需求的精确率与召回率，以及提示密度、出现时机和闪烁体验。
- 显式与隐式行为对熟悉度的信号质量。
- 模型时延、缓存命中、单位观看小时成本和隐私边界。

这些需要通过探索验证、人工标注集和实际用户观察验证，当前均不能当成已证实事实。

<a id="delivery-sequence"></a>

## 交付顺序

1. 架构
2. 数据模型
3. API 与最小贯通骨架
4. 提示编排引擎
5. Chrome 扩展
6. 学习归约模型
7. 生产化

每一阶段先明确决策、替代方案与取舍，再进入下一层。当前只激活阶段 1；SQL 字段、具体端点、Compose、提示词和业务代码等待架构确认。
