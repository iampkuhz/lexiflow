# 1. LexiFlow 产品说明

**位置：** [文档首页](../README.md) → 产品说明。**下一步：** [系统总览](../architecture/overview.md)解释这一体验由谁提供；[产品术语](glossary.md)解释词段和资料。阶段目标见[路线图](../roadmap/master-plan.md)，交付进度仅见[状态页](../roadmap/master-plan/status.md)。

LexiFlow 面向观看英文视频、想保留原文又不愿被整句翻译打断的用户。它基于已发布资料，为有价值的词、短语或术语显示简短中文提示。**英文是始终可用的主体验；一期多义词使用已按候选顺序确定的默认首义，接受它在部分语境下不准确，不因多义直接放弃提示。**

## 1.1. 一次观看中用户看见什么

1. 用户播放有英文字幕的普通 YouTube 点播视频；Chrome 扩展读取已渲染英文字幕，英文不等待网络或提示。
2. 扩展请求当前词段的提示。服务端只查已发布资料并运行确定性规则；一期读取默认首义，词库命中不等于当前语境适用。
3. 若返回符合发布规则且仍匹配当前字幕的结果，扩展在对应英文词段后放一条简短中文释义；仅整体提示的多词词组加连续黄色底线（包含词间空格），单词提示不画线，相邻独立提示不合并；否则保留英文，不补整句翻译。字幕切换、seek、导航或晚到响应都不能让旧提示留在新字幕上。
4. 用户明确选择“不再提示”时，扩展仅在本机保存与词段和词库版本绑定的抑制偏好；不上传，也不把观看、点击或停留推断成熟悉度。

技术调用与失效路径从[观看流程](../architecture/flows/viewing.md)下钻；来源与展示的长期约束见[产品架构规范](../../openspec/specs/product-architecture/spec.md)。

## 1.2. 产品边界与质量取舍

首个客户端是 Chrome 扩展，首个来源是 YouTube 英文字幕。单词、短语和专业术语都可成为候选，但只在已发布词库、适用的语义资料和规则共同支持时提示。缺少可用已发布资料、后端不可用、字幕不可靠或默认义项无效时退化为仅英文；一期支持多义词，显示导入期按候选顺序确定并校验发布的第一义，不显示整份多义列表或未经审核的模型结果。

完整词库只提供候选，不等于逐词翻译。发布时标记 来源明确标记的全部 Oxford 基础单词与固定功能词，不按排名或数量截断；观看时接收已处理、非基础、具有合法默认中文短释的单义或多义候选，排除来源中冠词或否定词起头、介词结尾等不完整短语。提示词段必须互不重叠，不设置固定三条上限；有来源排名的学习词先于未排名的来源短语，同层再考虑复杂词表证据和长度。同一区间命中多个不同词条且身份无法确定时保持英文；同一词条的多个义项则使用已发布的默认第一候选。重要性决定是否提示，默认排序决定一期显示什么；这不是通用的词义消歧。

整句双语字幕增加遮挡和阅读切换；更多中文并不自动提高语境准确性。因此产品同时关注提示准确性、覆盖、密度、出现时机、闪烁和请求耗时，而不是仅统计词库命中。需要用真实样本验证这些取舍，文档本身不是体验证据。

## 1.3. 不属于观看的改进链路

[第三阶段](../roadmap/master-plan/improvement.md)规划在观看之外分析缺失资料；模型可用于产生待校验材料，但须经过评估、审核与版本发布，**只供后续观看读取**。观看请求不能发起、等待、预取或订阅模型工作。普通字幕请求也不构成采集、持久化、外发字幕或反馈的授权。两条链与发布关系见[流程总览](../architecture/flows.md)。

账号、服务端个人档案、自动行为评分、跨设备同步、整句翻译、复习系统、推荐与社交不属于已授权能力。新增来源或能力须先重新确认可靠文本、身份、隐私和产品范围，不能借本地抑制偏好扩展成个人画像。
