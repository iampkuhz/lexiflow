# 1. LexiFlow 产品说明

> 当前产品决策以本页和已接受的 OpenSpec 为准：LexiFlow 提供通用语境提示，不提供账号、个人词汇档案、学习行为追踪或跨设备同步。

## 1.1. 问题

整句中英双语字幕会遮挡英文并增加阅读切换；词典最高频释义也常忽略当前专业领域和上下文。LexiFlow 保留英文，只在具有语境价值的词、短语和术语旁增量显示简短中文提示。

```text
This could materially impair（实质性损害） settlement finality（结算最终性）.
```

## 1.2. 产品目标

- 英文字幕始终是主内容，提示注释不能阻塞观看。
- 系统基于共享词库、内容上下文和确定性规则选择值得提示的词段。
- 模型只处理语境消歧、术语、短语和中文表达；业务不绑定单一模型 API。
- YouTube 是首个内容适配器；网页、PDF、播客和其他视频平台复用核心内容与提示能力。
- 服务端只维护通用内容、词库、提示工作和运行结果，不维护用户状态。

## 1.3. 首版非目标

- 账号、认证、设备注册、多人使用、个人词汇档案、行为反馈、学习评分或跨设备同步。
- 整句双语字幕、每句完整翻译、完整复习系统、内容推荐或社交能力。
- 概率模型、向量数据库、Kafka、Kubernetes、服务网格或大规模微服务。
- PDF、播客、网页和其他视频平台的产品实现。

## 1.4. 首个最小可用版本边界

- Chrome 扩展 + 有英文字幕的普通 YouTube 点播视频。
- 单词、短语、专业术语三类通用提示注释。
- 一个真实语义供应商和确定性模拟实现。
- 浏览器 L1、Redis 和 PostgreSQL 分别承担可重建缓存、热点缓存和服务端事实。
- 模型、工作进程、Redis 或后端失败时，英文观看仍可继续。

## 1.5. 待建立的产品证据

- YouTube 字幕在人工/自动字幕、长视频和直播回放样本中的获取稳定性。
- 当前句和有限前后文是否足以支持高质量消歧。
- 通用提示规则的精确率、召回率、密度、出现时机和闪烁体验。
- 模型时延、缓存命中、单位观看小时成本和内容隐私边界。

这些需要通过探索验证、人工标注集和实际体验观察验证，当前均不能当成已证实事实。

## 1.6. 交付顺序

1. 架构
2. 数据模型
3. API 与最小贯通骨架
4. 提示编排引擎
5. Chrome 扩展
6. 生产化

每一阶段先明确决策与取舍，再进入下一层。当前只激活阶段 1；SQL 字段、具体端点、Compose、提示词和业务代码等待架构确认。

## 1.7. 第一阶段验收案例

验收案例与后续实现或验证任务一一映射；映射不得存在孤儿或重复项。

### 1.7.1. LF-CAPTION-001 · P0 · 英文优先

- **前提：** 客户端收到当前英文字幕。
- **当：** 后端、Redis 或语义供应商超时。
- **则：** 英文在客户端本地时延预算内显示，且没有整句中文替换。
- **证据负责人：** Chrome 扩展集成测试（阶段 5）。

### 1.7.2. LF-ENRICH-001 · P0 · 规则与模型分离

- **前提：** 候选词段被共享词库和规则判为常见且缺少语境价值。
- **当：** 提示编排执行提示需求判断。
- **则：** 候选可在不调用语义供应商的情况下被抑制。
- **证据负责人：** 提示编排架构/单元测试（阶段 4）。

### 1.7.3. LF-ENRICH-002 · P0 · 待处理状态必须有持久交接

- **前提：** 快速通道可返回确定性提示注释。
- **当：** 语义交接提交失败。
- **则：** 响应不能宣称语义任务待处理，英文和快速结果仍可使用。
- **证据负责人：** 提示编排/应用失败测试（阶段 4）。

### 1.7.4. LF-ADAPTER-001 · P1 · 来源独立

- **前提：** 新的内容适配器能产生规范化片段与上下文。
- **当：** 它接入组合根。
- **则：** Content、Lexicon、Semantic 与 Enrichment 核心不需要依赖来源平台代码。
- **证据负责人：** 模块边界测试（阶段 5）。
