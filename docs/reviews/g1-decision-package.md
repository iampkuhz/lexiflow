# G1 / 阶段 1 架构决策包

> 变更：`establish-lexiflow-foundation`；目录任务：`LF-TSK-ARCH-0008`；评审项：`LF-DECISION-P1-001`。
> 本文是架构决策提案；阶段进度只在[第一阶段状态页](../roadmap/phase-1-status.md)维护，不构成 G1 `PASS` 收据。

## 决策背景与推荐

LexiFlow 的首个闭环是 Chrome 扩展在 YouTube 英文字幕上提供少量语境化中文提示。英文必须先显示，不能被整句中文翻译、网络请求或模型等待取代。服务端持有跨设备个人词汇档案；YouTube 只是第一个来源。[产品说明](../product/product-brief.md) 和 [阶段 1 架构](../architecture/phase-1.md) 已把这条产品边界、七个限界上下文、两条完整流程与同步/异步边界写成提案；[用户需求追踪表](phase-1-user-requirement-traceability.md) 把附件中的六项阶段 1 输出及主要产品约束逐项映射到当前证据；[阶段 1 横切合同](../architecture/contracts/README.md) 进一步固定语义端口/结果、缓存、威胁、可观测性和来源适配的架构语义；[产品架构规范](../../openspec/specs/product-architecture/spec.md) 固定长期行为约束。

推荐整体接受下列架构方向，并把本页数值目标仅作为下一阶段探索验证的初始实验阈值。若有一项不接受，应指出要替换的 ADR、原因和必须保持的产品不变量，再修订对应设计与 Gate 输入；不能用口头例外绕过英文优先、权威状态和真实验收。每条方案的完整理由、后果与复审触发器见 [ADR 记录](../architecture/decisions.md)。

| 要确认的选择 | 推荐方向 | 方案比较与取舍的唯一正文 |
|---|---|---|
| ADR-001 / ADR-002 | 模块化单体，同一版本的 `api` / `worker` 组合根 | [系统组织](../architecture/decisions.md#系统组织用业务边界控制复杂度) |
| ADR-003 / ADR-007 | 英文优先、规则快速通道、供应商无关语义端口 | [观看体验](../architecture/decisions.md#观看体验让语境帮助不拖慢英文) |
| ADR-004 | 来源无关核心，YouTube 是第一个适配器 | [内容来源](../architecture/decisions.md#adr-004内容核心来源无关youtube-是适配器) |
| ADR-005 / ADR-006 / ADR-008 | 不可变学习事实、显式投影、PostgreSQL 持久交接；缓存可重建 | [事实正确性](../architecture/decisions.md#事实正确性接受应用与恢复各有边界) |
| ADR-009 / ADR-010 | 机器合同与分层验收；Java 25 后端、TypeScript 扩展、独立 Python 工具链 | [工程约束](../architecture/decisions.md#工程约束让实现和证据各有负责人) |

`LF-TSK-OPS-0001` 对应 ADR-010 和[批准后复现计划](../development/post-approval-toolchain-verification.md)：Gradle Wrapper、严格依赖锁、精确运行时、错误运行时/缺锁负例和双环境重建均须按阶段提供证据。Node 等工具版本以对应清单及 ADR 为准，不在本页重复配置。技术方向认可不等于工具链目录验收，已有工程文件也不能证明业务或双环境复现完成。

## 初始 SLO 与预算假设

本表是初始数值目标与测量依据的唯一文档来源，**尚未测量、尚未承诺**。评审应确认这些阈值是否适合作为首个探索验证的目标，以及应在哪类机器、网络、字幕样本和标注集上测量。平均值不能代替 P95/P99；客户端首屏与后端、队列、供应商、投递必须分段统计。

| 指标 | 初始目标 / 预算 | 验证与调整依据 |
|---|---|---|
| 英文字幕到可见 | 本地路径 P95 ≤ 50 ms；不包含后端/模型等待。 | 扩展探索验证测播放器字幕、叠加层和长视频样本；即使全部增强失败，英文仍可见。 |
| 浏览器 L1 提示注释 | P95 ≤ 20 ms。 | 测版本校验、缓存命中与实际渲染，不能把命中载荷当作已显示。 |
| 后端确定性提示注释 | P95 ≤ 250 ms、P99 ≤ 500 ms。 | 在缓存命中/未命中、个人档案查询与 Redis 故障样本中分段测量；供应商缓存未命中不进入必需快速路径。 |
| 异步语义提示注释 | P95 ≤ 2.5 s；超过截止时间静默降级。 | 分开测持久交接、队列等待、供应商、结果持久化及投递；延迟结果必须拒绝陈旧字幕/个人档案。 |
| 跨设备学习收敛 | 显式 known/unknown 在其他活动设备 5 s 内生效；被动事件 60 s 内影响个人档案。 | 显式动作同会话读己之写优先；多设备/离线/重复与投影失败需独立验证。 |
| 提示质量 | MVP 标注集提示词段准确率 ≥ 85%；语境化提示人工可接受率 ≥ 80%。 | 固定人工标注集并同时观察召回率、提示密度、闪烁和打断感；不能只优化准确率。 |

成本与交互预算目前只有约束，**没有可证实的数值上限**：模型调用不得随每句字幕无条件发生；规则、词库、个人档案与兼容缓存先过滤候选；每次任务有截止时间，客户端在超时后不等待；默认日志不保存完整字幕、模型输入或个人词汇历史。单位观看小时的供应商成本、缓存命中、每句提示数量和长期事件保留费用须由真实观看样本测量，再由产品负责人设上限。现在给出金额或每句固定提示数会制造未经验证的承诺。[产品说明的待验证证据](../product/product-brief.md#product-evidence-to-establish) 已列出相关实验。

规划容量只见[长期计划](../roadmap/master-plan.md)，调度参数只见[共享策略](../../harness/agent-policy.manifest.yaml)，不作为本页架构批准条件。

## 用户决定的边界与阶段 2 入口

评审时需要对十条 ADR 的推荐方向，包括 `LF-TSK-OPS-0001` 对应的 ADR-010，以及本页初始时延、学习收敛、质量和成本测量方式给出接受、修改或拒绝的决定。可附条件接受某个目标，但必须把条件写入相应 ADR/验收任务；本页不会提前把 `Proposed` 改成 `Accepted`。G1 的可执行证据、技术栈任务验收和显式用户决定均完成后，目录的 `LF-TSK-ARCH-0008` 才能成为阶段 2 入口任务的有效前置收据。[G1/G2 阶段 gate](../../planning/workstreams.yaml) 要求上一 Gate 退出任务为 `PASS` 且有 `APPROVED` 用户确认，不允许仅凭文档已写或任务已派发开启 P2。

确认后阶段 2 只进入 **数据模型 / 数据合同**：按既定负责人定义身份、内容、词库、个人词汇、提示注释、学习归约事件的聚合与不变量；事件幂等、乱序、重放与来源证明；迁移、访问模式、保留/删除边界及 G2 证据。阶段仍须先比较方案与取舍，再设计具体数据结构。具体 API、提示编排业务实现、Chrome 扩展行为、学习归约算法和部署编排分别由后续 Gate 激活；本页不预设 SQL 字段、REST 路径、Compose、提示词或具体供应商。

审批顺序与工具链阶段边界见 [第一阶段验收顺序](../development/validation/06-phase1-decision.md)。
