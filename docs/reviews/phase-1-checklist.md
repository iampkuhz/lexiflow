# 阶段 1 架构审查检查清单

`LF-DECISION-P1-001` 只有在下列项目被明确接受或记录为待决时才能完成。

<a id="product-boundary"></a>

## 产品边界

- 个人词汇档案是服务端核心资产；扩展只缓存、渲染和采集行为。
- YouTube 被定义为内容适配器，未来来源不需要复制核心学习逻辑。
- 生成、投递、实际展示、点击四类事实没有混用。
- `HintDisplayed` 只在当前字幕的提示真正渲染后上传；晚到且未展示的提示注释不形成学习证据。

<a id="domain-ownership"></a>

## 领域归属

- 身份/设备、内容、全局词库、个人词汇、学习归约、提示编排、语义、客户端投递/同步、平台各有唯一负责人。
- 任一持久状态都能回答“哪个领域可以修改它”。
- 跨领域依赖通过公开合同，禁止跨表访问和具体适配器反向进入核心。
- 学习归约到个人词汇是更新命令，提示编排到个人词汇是版本化只读快照，避免循环依赖。

<a id="runtime-flow"></a>

## 运行时流程

- 英文字幕显示路径不包含网络、后端或模型前置条件。
- 确定性提示编排快路径有明确时延预算和降级结果。
- 语义缓存未命中使用增量异步结果；迟到结果必须由字幕/上下文/配置档案/引擎版本防止误应用。
- 只有持久交接成功后才能在快速结果声称待处理；失败时返回无待处理任务降级。
- 学习归约事件先可靠、幂等保存再 ACK；个人档案投影允许重放并处理重复、乱序与多设备输入。
- 显式 known/unknown 的最终响应必须区分个人档案已投影与待补投影，不得先 ACK 事件再假定下一请求能读到新版本。

<a id="cache-and-failure-isolation"></a>

## 缓存与故障隔离

- 可共享的语境化含义与用户专属提示需求决策分开缓存。
- PostgreSQL 是事实来源；Redis、浏览器缓存和投影可重建。
- Redis、语义供应商、工作进程或后端不可用时，英文观看仍成立。

<a id="semanticsecurity-与-source-contracts"></a>

## 语义、安全与来源合同

- 语义只暴露 `disambiguate`、`translateInContext`、`extractPhrase`、`explainSentence` 等任务级能力；领域不依赖供应商 SDK、模型名、提示词或传输错误。
- 语义的成功、放弃回答、格式错误、超时、拒绝与迟到结果有稳定结果语义；语义证据不直接决定是否展示。
- 扩展、API、工作进程、存储和供应商的信任边界、最小输入、凭据负责人与滥用场景已明确。
- 关联、日志、指标、追踪和脱敏能关联快速/慢速/学习归约流程，同时禁止默认记录完整字幕、模型输入和个人词汇档案。
- YouTube、网页、PDF 与音频都通过来源无关内容合同表达；能力缺失、缺失和乱序不会触发猜造。

<a id="delivery-architecture"></a>

## 投递架构

- 模块化单体是当前默认；`api` 与 `worker` 是组合根而非业务微服务。
- 当前没有引入 Kafka、Kubernetes、向量数据库、服务网格或完整事件溯源。
- 模块边界计划由构建依赖和架构测试强制，而不只依赖文档。

<a id="technology-and-reproducibility-proposal"></a>

## 技术栈与可复现方案

- 推荐基线是 Java 25 LTS + Spring Boot 4.x + Gradle 9.7.x 后端，清单 V3 + TypeScript 6.x + Node 24 LTS 扩展，以及独立 Python 3.12 工具链；三套候选方案和取舍已审阅。
- Java 领域保持纯 Java；Spring、数据库、Redis、HTTP、Chrome 与供应商 SDK 只进入适配器/组合根。
- Python 3.12 仅用于阶段 1 Harness，已记录 security-only/EOL 风险、升级阈值和不晚于 2027-10 的复核窗口。
- 批准后必须精确锁定运行时、Wrapper、发行包/JAR 校验和与依赖图；多项目/包含的构建严格锁、错误运行时、缺锁、双环境清理后构建和架构测试都有计划证据。
- 产品构建必须由确定性启动器选择固定 Java 25，不继承开发机默认版本；正式当前输入收据与批准后的独立干净环境复现分别核对。

<a id="gate-and-evidence-boundary"></a>

## Gate 与证据边界

- OpenSpec 变更内的检查清单、独立文档审查、Qoder 退出 `0`、回调 queued 和引导验证都不等于目录 `PASS`。
- 规划验证器、验收控制面与派发文件声明预检必须按目录 DAG 完成，并在最新冻结输入上运行必需检查。
- 每个正式收据固定任务/变更/运行/代理/父级身份、输入哈希、命令/退出码、验收/效果/风险和变更文件声明对账；latest 指针不作为证据。
- G1 只有在必需收据聚合为 `PASS` 且用户明确 `APPROVED` 后才开放阶段 2；任何跳过、未运行或不可用都不能聚合成 `PASS`。

## 需负责人批准的初始目标

- 这些数值是待验证假设，不代表已测量或已承诺 SLO；本清单不维护第二份数值表。
