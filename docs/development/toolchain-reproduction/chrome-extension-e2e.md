# 1. Chrome 扩展双语提示体验与 E2E

## 1.1. 可见交互与失败边界

扩展只处理 YouTube 播放页中 `video`、`.html5-video-player`、`#ytp-caption-window-container` 与
`.ytp-caption-segment` 提供的可见英文快照。隐藏字幕、广告和跳转期间不请求提示。

英文不等待网络：完整英文先在稳定增强层即时显示，再可逆裁剪原生重复绘制，不修改来源节点。中文仅在 `READY` 响应绑定同一原文、合法来源引用与发布版本后原位补入，例如 `A reliable(可靠的) result.`。保留来源可见分行，中文增加后允许自然换行；无提示和请求失败仍保留同层英文。来源失效、广告、导航或关闭增强时解除裁剪，恢复原生绘制。

MutationObserver 在绘制前检测新快照，立即取消旧请求并替换为当前英文，然后才执行异步摘要与短暂请求合并。摘要完成及结果显示时都重验当前字幕，不重试、不积压；相同文本在 seek 后也不能复用旧提示。展示和请求边界、计时阈值唯一见[基础体验](../../roadmap/master-plan/foundation/experience.md)。客户端不截断文章、不选择首义；后端无可靠资料返回 `NO_PENDING`，不创建模型或异步补全任务。

## 1.2. 本机构建、安装与体验

完整的依赖、API 启动、词库选择和扩展安装步骤统一在[首页](../../../README.md#本地启动)。
API 默认供扩展访问的地址为 `http://127.0.0.1:18080`；使用完整词库前须[导入并发布](lexicon-import.md)。

若默认端口已被其他实例占用，可用 `python3 -m scripts.environment.start_api --port 18081` 启动独立实例，并以
`LEXIFLOW_API_PORT=18081 npm --prefix extension run build` 构建扩展。构建参数只允许本机端口，不能配置远端主机；
生成的 API 地址与 host permission 使用同一端口。常规测试会重新构建默认端口，实际安装前须按所选端口再次构建。

源码更新后需要重新构建 `extension/dist`、刷新扩展并刷新播放页；后端改动需重启 API。扩展只请求
当前字幕，不持久化字幕或观看历史，不向服务器上传本机抑制偏好。点击中文可抑制对应词条；
`LF` 菜单可恢复全部提示、查看聚合诊断和清空统计。工具栏弹窗可开关当前页面增强；关闭立即恢复原生字幕并停发请求，刷新或换视频恢复开启，其他标签页不受影响。偏好限制及失败边界见[基础体验](../../roadmap/master-plan/foundation/experience.md#12-字幕与展示)。

## 1.3. 自动化验证

```bash
cd extension
npm ci
npx playwright install chromium
npm test
npm run e2e
```

单测验证原文绑定、区间、单义短释义、状态一致性、多个词段排序、字符边界、取消和迟到响应。
E2E 加载真实 Chromium 扩展，使用合成 YouTube 页面、独立本机 API 与内置确定性词库；不复用
用户正在运行的 API，不读取真实模型密钥或请求真实模型。测试覆盖行内位置、标点保留、原字幕未改写、
绘制前清除、来源隐藏、广告、seek、空结果、超长输入和网络降级；本机抑制在刷新后保留、恢复后重新展示，
偏好操作不调用后端。新增 popup 集成测试只将活动标签查询绑定到本地夹具，弹窗文档和跨扩展消息是真实执行；覆盖开关、在途取消、导航重置和陈旧操作拒绝。

需要连续运行和布局验收时，在同一目录显式执行：

```bash
LEXIFLOW_EXTENDED_ACCEPTANCE=1 LEXIFLOW_SOAK_SECONDS=375 npm run e2e
```

扩展验收沿用自动化脚本的临时 Chromium profile 和完全路由到本地 HTML 的夹具，不触及用户 profile 或真实网站。
以实际墙钟连续运行 375 秒，逐句检查英文即时保留、旧结果清除、最终提示与有界统计；短时参数只作诊断，不能冒充完整连续运行证据。
布局覆盖普通/窄窗口、夹具全屏、150% 文字字号、长字幕和三提示。三提示使用明确标注的 renderer 合同 mock，其余布局与连续运行调用实际内置 API。
报告及截图位于 ignored `tmp/quality/extended-acceptance/`，必须人工查看截图，不仅检查几何断言。

这些检查证明浏览器与 API 的工程链路，不证明实际词库的语境准确率或真实 YouTube 适配效果。

## 1.4. 来源合同限制

YouTube 渲染 DOM 只提供屏幕文本快照与播放器读数，没有可靠的轨道修订或真实字幕起止时间。
本机序号、观察修订与摘要只用于当前请求的去重、取消与迟到结果拒绝，不得充当持久内容修订或共享缓存键。

字幕过短或资料查询太慢会使提示被放弃；扩展不延迟英文，也不把旧中文延续到下一句。实际页面选择器、
字幕布局与全屏兼容性仍需本机体验核对，不兼容时应降级到原英文字幕。

## 1.5. 日志与排障

播放器的 `#lexiflow-caption-overlay` 元素通过 `data-lexiflow-diagnostics` 提供本机内存聚合：
采集、合并等待、传输、词库查询、规则、API、渲染和端到端耗时；包含总计数及最近 256 个样本的 p50/p95。
无样本的百分位为 null，不冒充零耗时。API 用 `Server-Timing` 返回服务端自身计时，客户端不相减跨进程时钟。
扩展 service worker 的 `[LexiFlow]` 日志仅给出结果和请求耗时。诊断应区分资料缺失、查询耗时与结果格式错误，不把在线模型配置作为观看的前提。配置参数与常用排障入口见[首页](../../../README.md#没有效果时看哪里)。

`cancelled-acquisition`、`cancelled-before-request`、`cancelled-in-flight` 区分失效位置；`late-ready` 表示已返回提示但过期丢弃，`stale-at-render` 表示最终显示校验拒绝。取消可能来自换句、跳转、关闭等，不能全算成延迟漏译。`missing-server-timing` 记录成功响应缺少服务端完整计时；不同阶段样本数可能不同，不能直接相减其均值或百分位。

日志不包含字幕原文、视频 URL、模型输入输出或密钥，不开启 HTTP 请求体调试日志。`timeout` 与主动取消的 `aborted` 分开；`NO_PENDING` 是无可靠提示而非成功翻译。
