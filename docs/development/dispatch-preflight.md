# 1. 派发预检

派发预检只回答“冻结工作包能否安全开始写入”，不代表产品或 Gate 验收。它对候选任务、同版本目录快照和
活动实例运行纯判定器，返回稳定的 `PASS`、`BLOCKED` 或 `FAIL`。

## 1.1. 冻结输入与判定

`check_dispatch(candidate_view, catalog_snapshot, active_instances)` 核对任务 ID、版本、描述符哈希、
负责人、`allowed_files`、写声明和 `produced_contracts`。路径只接受仓库相对 POSIX 精确路径、末尾
`/*` 与 `/**`；绝对路径、`..`、反斜线、控制字符、符号链接、大小写歧义、重叠或重复声明为 `FAIL`。

| 结果 | 条件 |
|---|---|
| `PASS` | 全部声明完整、一致，且与活动实例无写入或公开合同冲突。 |
| `BLOCKED` | 确认存在写入交集或同一公开合同的多个写入者。 |
| `FAIL` | 输入、路径、owner、版本、哈希或快照无法证明安全。 |

## 1.2. 验证边界

测试使用合成任务和路径，覆盖合法输入、任务/版本/哈希不一致、owner 缺失或跨越、路径风险、写入冲突和
合同冲突。`PASS` 只对提交快照和有效调度窗口成立；调用方仍须完成实际派发并遵守共享 policy。预检不读取
进程、不持锁、不管理租约，也不证明活动列表完整、跨进程原子派发、Qoder 生命周期或 Gate 验收。
