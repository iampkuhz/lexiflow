# 1. 派发预检

派发预检解决的是“这个工作包现在能否安全开始写入”，不是“这个工作包是否已验收”。它采用**纯输入判定器和一次性 CLI 适配器**：调用方提交冻结的候选描述符、目录快照和活动实例；预检只返回稳定的 `PASS`、`BLOCKED` 或 `FAIL`。

## 1.1. 核心判定模型

预检将候选与所有活动实例对账同一份目录快照，检查任务版本、负责人、`allowed_files`、写声明和公开合同生产者。允许范围与写声明必须完全一致；不同写入者的路径空间不能相交；同一公开合同不能同时有两个写入者。路径比较是有限语法的符号判定，不依赖文件此刻是否存在。

输入不完整、非法或无法证明路径安全时为 `FAIL`；已确认的范围、负责人或合同写入冲突为 `BLOCKED`；只有全部声明完整且没有冲突才为 `PASS`。这三态只反映提交快照，不能扩大为产品/Gate 的通过结论。

## 1.2. 调度边界

`PASS` 不证明活动列表真实完整，也不消除检查到派发之间的竞态。调用方必须证明非终态筛选和实例身份真实，并在同一有效调度窗口完成派发。预检不读取进程、不持锁、不管理租约；Qoder 单运行、回调和守护检查仍由共享 policy 约束。
