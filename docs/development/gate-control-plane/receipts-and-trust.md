# 1. Gate 控制面：收据与信任

## 1.1. 三态与收据

Gate 结果只有 `PASS`、`BLOCKED`、`FAIL`。必需检查未运行、跳过或证据缺失不能写作 `PASS`。`run` 在启动检查前持久化计划和开始事件，完成后写入不可覆盖的最终收据；`status` 只在完整最终收据存在时返回 `FINALIZED`。

收据至少绑定运行、任务与变更身份、receipt kind、冻结计划/输入/证据哈希、实际检查结果、签发者与生成时间。不得以完成信号、退出码或任意文本替代这些字段。

## 1.2. 身份隔离

签发者证据包证明本次 Gate 进程可以签发对应 receipt kind。调用者、实现者、独立审阅者和目录决定者的职责隔离由 policy 与证据包共同约束；实现者不能自行签发 validation/review，审阅层也不能重跑交付检查。

## 1.3. 当前输入链

计划、开始事件、最终收据和被消费的来源以哈希形成有向链。读取收据时同时核对定位、字节哈希、任务/版本、签发者和依赖；任一环缺失或不一致为 `FAIL`，而不是回退到历史 `PASS`。
