# 1. 后续阶段待办池

本页汇总尚未编入执行阶段的产品工作。每次由用户从中选取一组连贯事项，形成下一阶段的目标、合同、Task 和验收；池中顺序不是阶段顺序，列入池中不授予执行、采集或模型调用权限。

## 1.1. 待抽取事项

| 待办 | 具体问题与方向 | 抽取前置条件与验收重点 |
|---|---|---|
| Docker 平台扩展 | 增加 linux/amd64、Intel macOS、Linux 等宿主组合；现阶段仅 Apple Silicon macOS Docker | 每个新增组合独立原生构建、启动、更新恢复与资源验收，不用模拟构建或已有格式枚举代替支持证据 |
| 不提示词段管理 | 支持通过管理页面手工配置和维护明确不应显示中文提示的词段，例如将 `uh` 配置为不显示“嗯啊” | 明确匹配范围、规则生效与版本边界；仅对显式配置项生效，不推断用户熟悉度，也不替代扩展本机的个人抑制偏好；验证规则变更不会影响未匹配词段及英文原文展示 |

| 查询性能专项 | 基于聚合耗时与键数减少重复查询，优化预热比例、版本检查和缓存淘汰 | 第二阶段主线及观测可用；同资料样本对照 p50/p95、往返数、内存与回退 |

## 1.2. 详细边界

[查询与资料效率专题](performance.md)保存性能、资料及本地消歧试验的具体要求；[事后改进专题](improvement.md)保存分析和受控发布要求。它们是待办专题，不代表固定的第三或第四阶段。

本地模型试验与产品接入分别批准：试验不进入当前观看链路，若证据支持采用，先通过 OpenSpec 修订模型边界与资源合同。准确率约 80%～90%仅为此前提出的试验质量取舍，不是已测效果，也不是跳过独立评估的许可。

后续能力不成为基础观看或第二阶段重构的必经依赖；未抽取事项不建立假实现、空模块或正式完成记录。

## 1.3. 提示选择质量优化

先建立 50～100 条字幕片段的诊断样本，包含问题案例与正常案例；逐条标注系统实际提示、必须提示、可选提示、不应提示及释义是否符合语境。真实字幕、个人判断和诊断输出仅留在本机 ignored 目录，不提交仓库；共享回归测试使用合成或经改写的用例。

离线诊断按具体词段区分未收录、词形未匹配、基础词阻断、全基础或低信息短语阻断、超查询长度、释义不合格、同形歧义、重叠落选及客户端抑制。依据实际错误占比安排优化，每轮聚焦一类原因；不以统一放宽阈值、扩大预热或性能提速替代质量改进。

完整短语覆盖和人工核对资格、公共噪声治理与个人本机抑制分别处理；四词以上表达复用长短语识别待办，语境释义错误复用结构化多义项资产和前缀上下文选义待办。模型仅可按既有授权边界提供事后待审核资料，校验发布后供后续观看，不进入观看链路。

验收分别统计必须提示项的漏提示率、已显示项的多余提示率、语境释义正确率及每条字幕的提示密度；冻结指标口径和未参与调参的样本，核对正常案例回归。提示选择与释义质量分别报告，不以单一准确率或增减提示数量宣称整体质量提升；具体改善目标在抽取执行阶段时确定。
