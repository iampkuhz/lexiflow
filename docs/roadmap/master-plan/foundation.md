# 1. 第一阶段：词库驱动的基础体验

遵循[总路线图](../master-plan.md#11-核心原则)。本阶段回答：不依赖后续阶段，用户能否稳定获得可靠、及时的提示？

## 1.1. 目标与主要功能

- 调通 Chrome / YouTube 英文字幕采集、词段识别、规则筛选、资料查询和提示展示。
- 从已发布词库及语义资料中确定可用提示；可靠性不足时保持英文，不展示未经消歧的多义列表或首义。
- 建立字幕切换、跳转、后端异常和资料缺失时的安全降级与旧结果失效。
- 整理模块职责与依赖方向，建立端到端体验和响应时延的可复现基线。

## 1.2. 输入、输出与非目标

输入为有界字幕上下文、已发布资料和确定性规则；输出为绑定当前词段的可靠提示或不提示。本机显式抑制偏好只在扩展过滤，不上传。

不建设模型补全、事后分析系统、账号、个人画像或跨设备同步；不要求先完成高级缓存、批量预处理或自动更新体系。

## 1.3. 独立交付条件

- 基本提示路径能独立使用，模型服务和离线工作进程均不是运行前提。
- 缺资料、后端不可用、字幕切换时英文正常；错误或晚到提示不覆盖当前字幕。
- 以约定样本验证提示质量、覆盖和时延；具体指标在本阶段功能设计时确认，不以“能启动”替代验收。
