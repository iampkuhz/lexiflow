## 1.1. 已对齐事项

用户已确认三阶段、三级文档和观看链路不调用模型；已授权直接推进第一阶段及必要重构，要求可观测性、子功能独立验收、真实 YouTube 完整播放与截图检查。

用户已安装扩展并确认总体展示符合预期；本轮要求修正难词遗漏、多行变单行、原生字幕闪换、补足丢弃归因，并加入当前页面开关。实现遵循[基础体验](foundation/experience.md)，不以等待后端隐藏英文，不扩大采集、模型发送或账号权限。第二、三阶段不提前展开。

用户进一步确认：基础词排除扩大到约 2000 词，在导入预处理时打标；完全重复的释义也在预处理合并。观看不重新生成黑名单或合并释义，真正多候选词义消歧留到第三阶段，不默认取首义。

### 1.4.1. 本次真实使用的时延快照

只读采集已安装扩展的页面内存聚合：17 次观察、16 次请求、6 次提示、10 次无可靠提示；超时与晚到均为 0，取消 1 次。原计数不能判断这次取消在哪一段，也不能把无提示全部当成延迟漏译。页面开发日志未返回 LexiFlow 条目；后端分段数据来自实际响应的 Server-Timing，不冒充已取得本次后端原始日志。

| 阶段 | 样本数 | 平均耗时 | p95 |
| --- | --- | --- | --- |
| 采集/摘要 | 17 | 0.51 ms | 1.30 ms |
| 合并等待 | 16 | 156.58 ms | 159.10 ms |
| 传输及扩展消息往返 | 16 | 102.33 ms | 576.50 ms |
| 词库查询 | 13 | 29.03 ms | 46.16 ms |
| 规则 | 13 | 1.00 ms | 4.96 ms |
| API | 13 | 30.19 ms | 47.03 ms |
| 渲染事件 | 65 | 0.18 ms | 0.70 ms |
| 端到端 | 16 | 260.02 ms | 730.10 ms |

固定等待是明显成本；服务端内部查询占主要耗时，传输尾部仍需后续拆查。不同阶段样本数不同，不直接相减均值或百分位。最新代码的本地内置 API 连续夹具端到端均值 34.52 ms、最近 256 样本 p95 46.30 ms；这不是实际视频修复后的测量，不与上述真实使用数据直接作性能收益对比。

## 1.5. 下一步

交接扩展使用 18081 端口。预处理改造须先协调 V007 迁移和完整新版本导入发布，再切换 API；不要直接用新查询器连接尚无新增列的运行数据库。处理无关计划检查阻塞后，再形成完整 Verify 证据；Worker 启动单项已复测通过，整轮失败仍保留。用户在 default profile 重新加载并刷新测试视频后，复验多行、闪换、页面开关及目标词显示。继续记录语境质量缺口，不以提示数量替代准确度；正式收据另按独立身份合同闭环。
