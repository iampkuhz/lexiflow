# 1. 设计输入与冻结要求

## 1.1. 功能分类先于代码划分

由 ARCH 设计任务在正式启动后的主干上核对现状、调用者和资料合同，冻结每个步骤的输入、输出、owner、校验、失败去向和观测事件；再确定类、端口和数据库字段。以下是已经确认的设计方向，不是已经实现的产品说明。

| 维度 | 必须形成的确定结论 | 验收要求 |
|---|---|---|
| 词段类型 | 单词、完整短语、别名、屈折形的来源与关系；短语不按组成词的基础资格整体屏蔽 | 基础词独立出现不提示，但由基础词组成的可靠完整短语仍能提示 |
| 通用基础词 | 核对 全部来源 Oxford 基础单词加固定功能词（排名不影响基础资格）的现有选择依据；其他来源缺少证据不得套用 | 名单生成确定性、来源可核对、词形继承；不推断个人熟练度 |
| 重点词与长尾 | 冻结频率证据、学习词表证据、重点条件和排序；低频与缺少排名分别标记 | 重点词的合法默认释义、词形覆盖、提示优先级与预热资格可逐项验证；不承诺每次展示 |
| 资料质量 | 审查粗粒度短语过滤、释义错切、非法默认释义及来源噪声；每项有具体原因 | 可靠低频／无排名词段不被频率单独阻断；不可靠高频词不因排名绕过校验 |
| 提示与缓存 | 提示动作、提示优先级、缓存预热资格与预算独立计算；阻断词也可负向预热 | 不预热仍可按需查询；所有缓存依附发布身份，可失效重建 |

不得凭本次讨论臆定新的数值阈值、评分公式或白名单。正式设计任务须给出规则表、边界样例和唯一选定的决策；影响范围超出以上授权时重新交用户确认，未冻结不派发对应实现任务。

## 1.2. 预处理、启动与同步主线

### 1.2.1. 离线资料准备

来源解析 → 词条与词形规范化 → 分类证据生成 → 短语质量判断 → 默认释义准备 → 提示／缓存投影 → 校验及原子发布。

StarDict 与规范 CSV 各自解析，进入统一资料合同；保留来源，不伪造缺失频率或英文定义。同形不同词条保留全部候选。预处理冻结静态资格与原因；读取已发布投影的观看请求不再清洗词典、重排来源候选或重算基础词名单。默认首项不合格不偷偷以后一项补位。

资料发布和显式开发库重建分开。若实现确需改结构，仅修改最新 SQL，先在隔离环境验证重建重导；真实库操作另行确认，不由本次准备或未来 API 启动隐式执行。

### 1.2.2. 服务启动

检查运行模式与依赖 → 读取发布身份与预处理策略 → 有界正负缓存预热 → 输出可核对的就绪／降级结果。

正式模式不静默回退到内置演示词库；演示模式须显式选择。沿用预算作为待核对起点，而不是在本阶段承诺性能收益；不全量装载长尾、不执行导入、不启动模型。设计冻结时明确无发布版本、数据库不可用、预热部分失败和版本切换的行为，不能让消费者自行选择。

### 1.2.3. 当前字幕处理

1. 校验请求长度、快照结构、片段身份、范围和新增内容。
2. 计算连续新增区间，保留完整组的词边界与 UTF-16 坐标依据；旧片段不重复查询。
3. 生成连续 1～3 词查询键并去重；不扩为长短语穷举。
4. 绑定发布身份，读取正负缓存，将缺失键批量查询；版本不一致按冻结规则拒绝混合。
5. 定位词段，消费已发布动作和默认义，核对结果完整性；保留阻断／歧义证据，不能用预过滤掩盖同形冲突。
6. 执行同形多词条冲突、提示排序、重复及重叠选择；映射回片段 key 和局部偏移。
7. 返回处理覆盖与提示；客户端校验生命周期、字幕身份、迟到结果和本机抑制，再展示。

静态质量检查在预处理；原文范围、发布身份和响应有效性检查在运行期。不能为减少重复判断删除运行期安全校验。浏览器英文不等待以上流程；后台线程或 Promise 仍可能属于当前提示关键路径，不等于独立事后链。

## 1.3. 代码改造定位

| 现有实现 | 需要隔离的职责 | 实现 owner |
|---|---|---|
| `CachedLexiconQueryService`、`LexiconCatalog` | 字幕候选生成移至 Enrichment；Lexicon 只接受准确词形查询，缓存生命周期独立 | LEX 提供合同，ENR 适配消费者 |
| `HintPreparation`、`BasicVocabulary`、`LexiconPriority` | 分类证据、质量资格、提示优先级与预热资格分离 | LEX |
| `DeterministicHintPolicy` | 位置匹配、发布默认义与资格、冲突、排序及非重叠选择 | ENR |
| `EnrichCaptionUseCase` | 增量区间、结果坐标映射和请求级合并独立；移出诊断文本拼接 | ENR |
| `LexiconRepository`、`DefaultLexiconRepository` | 查询和发布端口及实现分离，不拆业务领域或数据库 | LEX、OPS；SQL 由 DAT |
| `LexiconImportMain`、`LexiconImportService` | 参数／格式／资源装配与预检、来源核对、发布用例分离 | LEX、OPS |
| `ApiApplication`、`CaptionHintController` | 启动模式、只读装配、HTTP 映射及观测边界 | API |
| `SegmentAnalysisLog` | 授权分析记录与普通日志分离；文件实现放适配器，经端口调用 | OBS 实现，API 装配 |
| `content.ts`、`stream.ts`、`overlay.ts` | 页面生命周期、采集快照、请求协调、展示和本机偏好各自归位 | EXT |

上表必须在最新主干重新核对，不能假定 phase1 收尾没有移动符号。只为实际消费者提取组件，不预建模型、worker、通用工作流引擎或空壳端口。公开 contract 与消费者切换按任务依赖串行，不维护双套兼容逻辑。

## 1.4. 日志与观测合同

普通结构化事件最低包含 `event`、`stage`、`result`、`reason`、`duration_ms`、聚合 `counts` 和适用时的 `lexicon_version`。请求使用随机关联 ID，不把它作为指标标签。结果统一遵守 Harness 结果语义；`NO_HINT` 是原因而非系统失败。

| 时机 | 内容与限制 |
|---|---|
| 启动终态 | 模式、资料是否可用、版本、实际预热数、耗时与固定失败原因 |
| 请求终态 | 新增区间数、查询键数、缓存命中／未命中数、数据库批次数、提示数、拒绝／丢弃原因及分段耗时；每请求有界汇总，不逐词 INFO |
| 状态切换／异常 | 发布版本切换、依赖故障、超时、取消和迟到丢弃；同类重复错误的抑制方案在合同中冻结 |
| 导入步骤与终态 | 输入、合格、阻断数量及原因分布、耗时、新版本或回滚结果；长步骤进度与“等待用户确认”区别处理 |

OBS 设计任务须补齐固定事件名、字段类型／单位、可空条件、原因枚举、打印级别、打印位置、开关及保留边界，并给出合成成功／空提示／故障样例。普通日志不含字幕、释义、观看地址、文件私有路径、JDBC 凭据或模型载荷。

本机敏感分析记录沿用已经授权的字段、去重、重启与写入失败语义，独立于指标与普通日志。当前同步写入不伪装为后台任务；异步化的持久交接、恢复、背压与丢失决策归后续待办。观测故障不改变提示业务结果。

## 1.5. 验收与工作包冻结

- 每个实现 Task 包含直接测试；设计 Task 输出可独立核对的合同和合成样例，图在功能合同冻结后按文档 policy 渲染、实际查看再入正文。
- 覆盖基础词与词形、包含基础词的完整短语、可靠低频／无排名词段、噪声短语、非法默认义、同形冲突、跨片段范围、增量追加与重复、版本切换、冷缓存、取消／迟到、分析写入失败及发布回滚。
- 性能计数用于定位与避免明显退化，不把本阶段包装为已经取得专项提速收益；规则变更与行为保持的拆分分别出具证据。
- 准备阶段的检查只运行规划／文档／策略投影静态检查。正式实现后采用当时 Harness 的同输入验证链，验证与审查身份分离，真实观看验证与合成测试分开报告。
- 所有 Task 派发前按冻结合同收紧文件 claim；预计超出 90 分钟或 8 个主要产品文件时按当前 Catalog 规则拆分，不以大范围 glob 掩盖不可验收的工作包。
