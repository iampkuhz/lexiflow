# 1. LexiFlow 长期计划

LexiFlow 的首个入口是 YouTube Chrome 扩展：英文字幕立即显示，系统仅对具有语境价值的词、短语和术语增量补充中文提示。用户可显式把词段标为“不再提示”，扩展只在本机保存该抑制偏好。产品不建设账号、多人使用、服务端个人档案或跨设备同步。

## 1.1. 计划原则

1. **英文优先且不阻塞播放：** 英文字幕走本地快路径；提示可异步增量到达。
2. **通用提示：** 词库、内容上下文和共享规则决定候选；模型只处理消歧和中文表达。
3. **持久工作先于待处理承诺：** 异步语义工作必须先确认 durable handoff。
4. **服务端事实与缓存分离：** PostgreSQL 保存服务端内容、工作和结果；Redis 与浏览器缓存可重建。
5. **最小学习反馈：** 只有用户显式选择才写入本机抑制偏好；显示、点击和停留不能推断熟悉度，也不上传为服务端画像。
6. **逐层冻结：** 每阶段先呈现已确定的总体方案、取舍和验收条件，再由 Gate 决定是否展开下一层。

## 1.3. 各阶段重点

### 1.3.1. P1：架构

冻结通用提示边界、模块职责、规则/模型分离、持久工作、YouTube 来源隔离与本机学习反馈合同。明确删除账号、服务端个人状态、自动行为归约和同步要求。

### 1.3.2. P2：数据合同

设计内容、词库、提示工作、语义结果、索引、保留、删除和迁移。先冻结概念和不变量，再进入字段与迁移脚本。

### 1.3.3. P3：API 合同

设计注释请求、增量结果、错误、取消、幂等请求身份和版本演进。合同测试先于消费方并行实现。

### 1.3.4. P4：提示质量

实现规范化、令牌/短语检测、词典查询、候选生成、提示需求、消歧、翻译和提示注释。规则与模型不得混成整句翻译调用。

### 1.3.5. P5：端到端体验

接入 YouTube、叠加层、本机缓存、离线恢复、浏览器 E2E 与可访问性；验证英文始终先显示。

### 1.3.6. P6：发布准备

验证密钥、日志、限流、观测、容量、备份、恢复、发布和回滚。未来内容适配器只在来源合同与真实需求证据成立后探索。

## 1.4. 里程碑

| 里程碑 | 用户可见范围 | 最小 Gate | 非目标 |
|---|---|---|---|
| MVP | Chrome/YouTube 上显示英文字幕与少量通用语境中文提示，并允许本机显式抑制词段。 | G1–G5；G6 的最小部署、安全和日志切片。 | 账号、服务端个人档案、自动学习跟踪、同步、多内容源、高可用。 |
| Alpha | 受控使用、供应商兜底、缓存、成本观测与恢复演练。 | G1–G6 的相关 P0/P1。 | 大规模增长与自动 ML 训练。 |
| Beta | 可控外部使用、兼容升级、容量和支持流程达到发布标准。 | G1–G6。 | 无负载证据的微服务/Kubernetes 扩展。 |

## 1.5. 扩展个人状态的门槛

任何未来账号、服务端个人档案、自动学习归约或跨设备同步提案必须新建 OpenSpec，并先给出用户价值、数据分类、认证/授权、删除与导出、冲突语义、迁移、威胁模型、成本和退出方案。没有明确用户批准，不得从缓存、请求关联或日志中推导替代身份。
