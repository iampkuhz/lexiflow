# 1. M 芯片 Mac：单容器部署和使用

> 入口：[LexiFlow](../../README.md)。正式使用不需要源码、脚本、Compose、Java、Node、Python 或单独数据库。

<a id="13-加载-chrome-扩展"></a>

## 1.1. 两步使用

前提是 macOS Apple Silicon、已安装并运行的 Podman、已安装的 Chrome，以及能够匿名拉取 GHCR 和下载 GitHub Release 的网络。这不是全新机器从零安装只需两步的承诺。

1. 在[正式 Release](https://github.com/iampkuhz/lexiflow/releases)复制该版本正文提供的完整 `podman run` 命令。它使用明确版本 `ghcr.io/iampkuhz/lexiflow:<softwareVersion>`，自动拉取唯一镜像、建立命名卷和启动一个容器。不要换成 `latest`；内容摘要与完整身份见同页 `release.json`。
2. 下载同页 `lexiflow-extension-<softwareVersion>.zip`，按同页 `release.json` 的 SHA-256 校验，解压到稳定目录；在 `chrome://extensions` 开启开发者模式，点击“加载已解压的扩展程序”并选择含 `manifest.json` 的目录。使用默认端口时无需填写地址、密码或修改文件。

安装只需要运行镜像、扩展 ZIP 和用于核验的 `release.json`。第三方对应源码、GitHub 自动生成的项目源码归档和发行证明不是运行依赖，不必下载或解压。

正式容器为 `lexiflow-release`，资料卷为 `lexiflow-release-data`；API 仅映射 `127.0.0.1:18080:8080`。数据库不映射宿主端口，所有持久事实在该独立卷内。运行命令资源上限为 2 CPU/2 GiB，Podman machine 还需要容纳其他项目；实际镜像大小、初始化时间和验证环境以对应 Release 的测量为准。

插件弹窗显示初始化中、正式就绪、服务不可用或版本不兼容。能否连接取决于双方的接口版本是否一致、服务是否就绪；扩展和后端的构建版本不必相同。容器在运行不代表它已经就绪。 后端按词库、偏好两个文件分别验证旧卷。若测试槽预检报告旧卷身份或结构不可证实，不要强制替换：保留原容器和卷，先处理报错的那个库。接口版本本身不决定旧卷能否复用。下载的 ZIP 不是 Chrome Web Store 安装，开发者模式和加载解压目录属于第二步；本阶段不提供商店上架或浏览器策略修改。功能以安装的正式 Release 为准：只有包含字幕档位、提示管理和词库查询的发行才提供这些操作；Release 页面列出的正式功能才适用于公开包。

## 1.2. 日常启停与隐私

```sh
podman ps --filter name=lexiflow-release
podman logs --tail 100 lexiflow-release
podman stop --time 45 lexiflow-release
podman start lexiflow-release
```

停止、启动及系统重启不重新导入匹配的已发布资料。首次初始化中断不会被标为成功；再次启动只在已识别的本项目卷上恢复核验，不清空未知数据。关键组件失败会使容器退出或健康检查失败，不能继续宣称就绪。

英文先显示，后端不可用或不兼容时仍显示英文。观看只查询已发布资料，不调用模型。可在“管理提示与词库”设置不提示英国国家语料库（BNC）高频前 1000、1500（默认）或 2000 词；弹窗只用于字幕开关、行数和简短状态。最近提示按本机后端时区汇总今天及此前 6 天的实际提示次数，并按次数降序排列，可搜索英文或中文并选择每页条数。从视频页弹窗点「打开管理页」，在「当前视频」查看可点击的视频标题（暂未读到标题时显示链接）及本页的词库名次与提示次数，不与近 7 天统计合计。打开或切回最近提示时立即更新，页面可见时每分钟更新；计数保存在本机，不因关闭 Chrome 清零。「最近提示」在宽窗口内并排显示两列，窄窗口显示单列。悬停或用键盘聚焦可对单条点「不再提示」，无悬停设备直接显示按钮；确认后词条从最近列表移出，可在「已停止提示」恢复。恢复只是解除个人抑制，仍受当前档位和系统提示规则约束。「词库查询」输入部分英文词形即可搜索，服务端每页返回 20 条，支持词频与 A–Z 排序。四个词汇列表统一为英文加中文释义的行内排版，宽窗口双列、窄窗口单列。

本机隐藏、档位偏好与每日提示计数保存在独立持久卷 `lexiflow-preferences` 中，挂载到容器 `/var/lib/lexiflow/preferences`，数据库为 `preferences.db`。后端只保留最近 8 天的每日计数，不保存字幕、视频或单次展示记录；偏好和计数不写入扩展存储、不上传。无账号、熟悉度推断或跨设备同步。仅本机安装使用者可访问；这不是对已控制本机的进程或恶意扩展的安全隔离。

服务诊断日志可能包含字幕正文及视频定位，只可本机查看，不上传、不提交。不要上传数据库、卷、密码、观看记录、模型输入输出或私有运行材料。分析文件默认不开启。

## 1.3. 更新和数据保护

先核对新版 Release 的镜像、扩展 ZIP 摘要和资料身份，准备好后再停止当前容器。镜像与扩展按同一 Release 配对，不能混装。

1. **旧服务继续运行时准备新制品。** 从新版本的 `release.json` 取得 `image.reference`、`image.configId` 和扩展摘要。先用 `podman image inspect --format '{{.Id}}|{{.Os}}|{{.Architecture}}' '<image.reference>'` 核对本机是否已有该摘要的镜像；仅在确认镜像缺失时执行 `podman pull '<image.reference>'`。确认镜像 ID 与 `image.configId` 相同（比较时可忽略 `sha256:` 前缀），且系统和架构是 `linux|arm64`。不匹配就停止。引擎可复用已缓存的相同层。校验新扩展 ZIP 后解压到另一目录，暂不启用。
2. **原名切换。** 核对旧容器的完整 ID、镜像、卷和启动参数，备份并保留已核验的旧镜像、卷和扩展目录。按完整 ID 停止旧容器，用不带 `--volumes` 的 `podman rm <完整 ID>` 只移除容器。新版本仍使用 `lexiflow-release` 和 loopback 18080；启动命令用 `--pull=never` 和已核验的 `image.reference`。仅在资料身份匹配时继续使用同一卷，否则用独立空卷，不改容器名。新服务就绪且身份匹配后，禁用旧扩展并加载新扩展；需要保留原扩展本机偏好时，不删除旧扩展或手工覆盖其目录。
3. **失败时原名恢复。** 核对本次新容器的完整 ID，停止并仅移除该容器。用保留的旧镜像、卷和启动参数重新创建 `lexiflow-release`，并重新启用旧扩展。新卷保留用于诊断。确认恢复就绪后才算回退完成。不用 `--replace`、不改归属标记，不让不同资料身份复用旧卷。

词库和偏好分别挂载到专属卷。既有偏好库不重写旧结构；缺表、列或约束不符时拒绝启动。资料身份变更时显式选择独立新卷，保留旧卷，不自动迁移偏好、旧词条 ID 或计数。

同名容器存在时 Podman 会清晰拒绝创建；重新启动已有容器用 `podman start`。已有端口被占用时先识别其归属，不停止未知服务。已有非空未知卷、资料或结构不兼容时入口失败关闭，保留现场。完全空的同名卷会被初始化；纯 `podman run` 无法区分它是本次自动新建还是预先存在，不保证拒绝所有未知空卷。

## 1.4. 失败定位

| 现象 | 处理 |
| --- | --- |
| 不能连接 Podman | 先完成基础环境安装并启动 Podman machine；应用命令不管理引擎。 |
| 拉取失败 | 检查 GHCR 网络及该 Release 的匿名可读性；不以其他来源或漂移 tag 替代已验 digest。 |
| 容器名或18080占用 | 核对实际资源所有者；不自动接管、替换或删除。 |
| 初始化中 | 等待实际资料导入；日志与容器健康提供进度，未就绪不能算成功。 |
| 容器退出或 unhealthy | 查看精确容器日志；不要删除卷重试。关键进程/资料核对失败必须修复原因。 |
| 版本不兼容 | 使用同一不可变 Release 的扩展和镜像，核对 `release.json` 身份；英文仍可显示。 |
| 英文有而提示无 | 打开弹窗查看当前字幕状态。「没有可显示的词汇提示」表示已经识别字幕，但当前没有词条可显示，不是等待整句翻译；「本句查词失败」则检查连接和版本。 |

## 1.5. 与开发环境分开

日常 Podman 只使用正式和试用两个产品槽位，停止容器也计入；源码调试优先启动独立 JVM。自动验收不占日常容器。

正式使用是 `lexiflow-release`/`18080`/`lexiflow-release-data`；开发调试、日常试用使用[本机固定槽位](../scenarios/local-development.md#131-固定试用槽位)，不共享正式卷。发行候选的 `18082` 属于独立验收宿主，不是日常试用地址。


Chrome 的正式扩展名是 **LexiFlow**，默认连 `18080`；**LexiFlow 测试版**的日常试用包默认连 `19081`，源码开发包默认连 `18081`。同一 Chrome 用户资料里，每个渠道对应一个固定扩展 ID；后续构建覆盖同一槽位，不靠目录名或版本号叠加。两套都可安装，但每个视频页只允许一套接管字幕。试用时先在 `chrome://extensions` 关掉另一套，再刷新视频页。

在弹窗点「打开管理页」，进入「服务连接」，修改预填的地址，再点「完成」。检查通过后才会切换；失败时保留原连接和输入，可直接修改重试。版本和复制诊断信息也在「服务连接」。只接受 `http://127.0.0.1:端口` 或 `http://localhost:端口`，不接受局域网地址、远程域名或路径。地址保存在当前扩展的本机存储；词条偏好仍保存在所选服务的本机数据库中。
