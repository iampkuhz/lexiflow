# 1. 语义处理流程与合同

本文说明 Enrichment 如何取得并标准化“词段在此上下文中的含义”证据。它不决定提示是否展示、不维护词库，也不接收账号、服务端个人档案或行为历史。本机词段抑制由扩展在结果匹配后处理，不进入语义请求。字幕提示的完整产品链路见[字幕提示流程](flows.md)，模块依赖见[模块边界](boundaries.md)。

## 1.1. 语义处理流程

本流程从 Enrichment 已选定、且规则允许继续处理的候选词段开始；候选提取、提示价值和密度判断仍由 Enrichment 的确定性规则负责。

| 步骤 | 处理 | 结论 |
|---|---|---|
| 1. 判断是否需要证据 | 规则抑制的候选直接结束；已有可靠且版本匹配的证据可直接复用。 | 规则不调用模型也能结束处理；模型不能推翻规则。 |
| 2. 确认后台工作 | 缺少可靠证据时，workflow 先持久化语义工作，再允许快速结果标为 `pending`。 | 持久交接失败时返回 `no-pending`，客户端继续英文或已有快速提示。 |
| 3. 生成语义请求 | worker 取得合法尝试后，Enrichment 以目标词段、有限上下文和版本生成一次任务级请求。 | 消歧和简短中文表达在同一任务中完成。 |
| 4. 调用并校验 | `:platform:adapters` 映射请求、调用真实供应商或确定性模拟实现，并把不可信响应按合同校验和转换。 | 供应商 SDK 对象、原始响应和运行细节不进入领域。 |
| 5. 发布或放弃结果 | Enrichment 接收标准结果后重验词段范围、内容修订和规则版本；匹配的结果才可持久化和投递。 | 晚到、失效或非成功结果不形成可展示提示。 |

步骤 2 的持久交接和步骤 5 的投递保证属于 workflow；语义能力只交付证据。语义成功也不等于提示已发布或已在屏幕展示。

## 1.2. 任务合同重点

### 1.2.1. 请求与结果

请求只携带任务所需的合同版本、词段身份与范围、内容/上下文修订、有界文本、目标语言、截止时间和取消信号。缺少必需上下文时不得补造字幕事实，应放弃或失败。

| 结果 | 必须满足 | 不得包含 |
|---|---|---|
| `success` | 与原请求、词段范围、内容修订和合同版本绑定；提供语境含义、简短中文表达与标准置信度。 | “必须展示”指令、供应商类型或自由格式运行数据。 |
| `abstained` | 明确表示证据不足或没有可靠答案。 | 空文本伪装的成功，或自造的高置信度。 |
| `failure` | 将格式错误、超时、拒绝、不可用、预算耗尽和取消归入标准分类。 | 可展示载荷、HTTP 状态、原始错误或供应商响应。 |

置信度只表示语义证据与当前有界上下文的匹配程度，不把供应商自评直接当作已校准概率。显示资格始终由 Enrichment 规则判断。

### 1.2.2. 职责与隔离

| 负责人 | 语义相关职责 |
|---|---|
| Enrichment | 声明任务和标准结果，提供语义需求，校验词段/版本/业务约束。 |
| workflow | 持久交接、合法尝试、取消、整体截止时间和尝试预算；不判断词义。 |
| `:platform:adapters` | 提示词、供应商 API、请求映射、不可信响应解析和标准结果转换；不自行无限重试。 |
| api / worker | 装配具体实现并触发用例；业务调用方不能选择供应商、模型或提示词。 |

首版按配置绑定一个真实实现，确定性模拟实现只用于测试。可替换要求同一任务合同和符合性测试，不要求动态路由或自动供应商回退。

## 1.3. 首版能力边界

首版公开的是一个“已定位词段的语境释义”任务：在有限上下文中返回语境含义和简短中文表达。以下名称只说明该任务的质量维度和范围，不构成首版的多个公开调用。

| 名称 | 首版处理 |
|---|---|
| `disambiguate` | 必需；判断目标词段在当前语境中的含义。 |
| `translateInContext` | 必需；合成绑定该词段的简短中文表达。 |
| `extractPhrase` | 候选词段提取必需，但先由词库与确定性规则完成；模型提取须在评测不足后另行提案。 |
| `explainSentence` | 不在首版范围，不建设句子解释入口或正常观看链路。 |

验收分别评估消歧正确性、中文表达质量和确定性候选边界；同时覆盖错误引用、低可靠性、格式错误、超时、拒绝、取消与预算耗尽。模拟实现与真实供应商实现必须满足同一合同，且规则可在不调用模型时抑制候选。

## 1.4. 隐私与观测边界

默认只发送任务需要的有限文本。原始整段转写、观看历史、账号标识、个人状态、会话凭据和无关内容不得成为隐式上下文；日志和指标只保留受控结果类别与聚合版本，不保存原始输入输出。供应商、模型与成本等运行元数据由基础设施和观测设施处理，领域只消费标准结果及必要的合同版本。
