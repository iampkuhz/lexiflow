### 5.1 资产与信任区域

| 资产 | 业务负责人 | 主要风险 |
|---|---|---|
| 用户、设备与会话身份 | 身份 & 访问 | 令牌窃取、会话混淆、越权。 |
| 字幕/上下文与来源位置 | 内容 | 私密内容泄漏、恶意内容污染、错误归属。 |
| 个人词汇档案与学习归约事实 | 个人词汇档案 / 学习归约 | 跨用户读取、行为伪造、不可解释篡改。 |
| 持久工作与提示注释结果 | 工作流协调/提示编排 | 重放、重复执行、篡改、陈旧投递。 |
| 供应商凭据、预算与路由策略 | 平台/语义 | 密钥泄漏、成本滥用、供应链风险。 |
| 日志、指标、追踪与运行证据 | 平台/可观测性 | 二次数据泄漏、不可控保留和关联识别。 |

信任区域如下：

1. **浏览器/页面区域**：网页、YouTube DOM、第三方脚本和页面文本不可信。
2. **扩展区域**：官方扩展代码可受浏览器上下文、旧版本或本地篡改影响；它是受限客户端，不是授权事实来源。
3. **公开网络 / API 边界**：所有客户端输入在此重新认证、授权、限流、规范化和绑定负责人。
4. **应用层 / 领域区域**：只消费已经通过入口校验的命令，但仍按领域不变量验证行为语义。
5. **工作进程 / 持久交接区域**：任务来自可信存储却可能重复、过期、旧版本或被错误配置；消费端必须幂等并重验合同。
6. **存储区域**：PostgreSQL/Redis 通过各领域出站端口访问；基础设施权限不赋予跨领域数据所有权。
7. **外部供应商区域**：供应商是外部处理方；输入必须最小化，输出始终不可信，凭据只能由服务端适配器持有。

<a id="52-boundary-crossing-rules"></a>

### 5.2 边界穿越规则

**必须**

- 网页内容只作为数据进入来源适配器；其中的指令性文本、标记或脚本不得改变系统策略、工具权限、供应商路由或观测规则。
- 扩展永远不能自证用户、设备、档案版本、学习归约效果或数据负责人。API 用服务端身份上下文重新绑定并校验所有引用。
- API 在持久化接收前限制输入大小、上下文窗口、语言/编码、引用归属、幂等身份和速率；失败输入不得进入领域或工作进程队列。
- 工作进程对作业身份、任务/变更合同版本、负责人、尝试/重试预算和陈旧/取消状态重新校验；重复交付只产生一次业务效果。
- 领域只能通过自己的端口访问存储；不得利用共享数据库权限读取其他领域表或绕过公开合同。
- 发送供应商的数据仅包含当前能力所需的有界文本和非个人化语义上下文；不得发送完整观看历史、完整个人词汇档案、会话凭据或无关转写。
- 供应商凭据只存在于服务端密钥边界；不得进入扩展、持久化载荷、日志、追踪、测试样例或供应商结果。
- 供应商输出经过大小、结构、语言、引用和语义合同校验；输出文本不得直接变成代码、查询、权限或路由指令。
- 遥测按[可观测性合同的脱敏与保留条款](observability.md#65-脱敏与保留)处理；生产数据不得复制到测试或代理交接。

**应当**

- 扩展权限保持最小宿主/功能范围，页面隔离层与高权限扩展层分开。
- API、工作进程与存储使用独立运行身份和最小权限；供应商适配器按供应商/环境隔离凭据与预算。
- 高成本语义能力同时受用户、设备、来源和全局预算保护，避免合法账号被自动化放大。

**后续条件**

- 阶段 2 固定授权、用户隔离、导出和删除控制；阶段 3 固定传输认证与输入限制；阶段 4 固定供应商数据处理；阶段 7 完成密钥轮换、恢复和外部安全测试。

### 5.3 威胁与滥用案例登记

| ID | 滥用案例 | 边界 | 必须控制 / 安全结果 |
|---|---|---|---|
| SEC-T1 | 恶意页面伪造字幕、超长文本、控制字符或指令性内容。 | 页面 → 扩展 → API | 本地隔离、规范化、大小限制；当作内容数据；失败时只显示原英文/原来源内容。 |
| SEC-T2 | 被篡改扩展使用他人内容/个人档案/结果身份。 | 扩展 → API | 服务端认证与负责人绑定；跨用户引用统一拒绝且不泄漏存在性。 |
| SEC-T3 | 离线重放、重复点击/展示或伪造学习归约事件。 | 扩展 → 学习归约 | 幂等身份、引用链和语义校验；客户端数值不能直接写熟悉度。 |
| SEC-T4 | 攻击者制造大量难句触发供应商成本。 | API/工作进程 → 供应商 | 能力允许列表、配额、总预算、回压与可观测拒绝；英文路径继续。 |
| SEC-T5 | 持久化作业重复、过期、版本不兼容或被错误路由。 | 存储 → 工作进程 | 合同/版本/负责人校验、幂等、陈旧取消；不产生重复提示注释/证据。 |
| SEC-T6 | 供应商返回格式错误、恶意标记、过长内容或诱导系统改变策略。 | 供应商 → 语义 | 标准化与约束校验；失败分类；原始输出不进入领域/遥测。 |
| SEC-T7 | Redis 键碰撞或共享语义缓存混入用户信息。 | 缓存 → 应用层 | 命名空间/版本/用户隔离、跨用户复用资格；可疑命中按未命中处理。 |
| SEC-T8 | 日志/追踪记录字幕、词项、个人档案、令牌或供应商载荷。 | 运行时 → 遥测 | 允许列表属性、集中脱敏、禁止字段扫描；事件保留但敏感值删除。 |
| SEC-T9 | 内部模块凭共享数据库绕过领域负责人。 | 模块 → 存储 | 仅端口依赖、最小数据库权限、架构/合同测试。 |
| SEC-T10 | 账号切换或撤权后离线 L1 继续显示前用户提示。 | 身份 → 扩展 L1 | 用户/会话绑定、主动清除、有限硬性过期、下一次鉴权拒绝。 |
| SEC-T11 | 来源修订号改变后旧提示注释被投递到新字幕。 | 投递 → 扩展 | 内容/字幕身份、修订号/个人档案版本比对；陈旧静默丢弃。 |
| SEC-T12 | 运维、测试或代理复制生产字幕与学习数据用于复现。 | 存储/遥测 → 工具 | 只用合成测试样例；受控诊断元数据；禁止真实数据进入仓库和交接。 |

<a id="54-acceptance-evidence"></a>

### 5.4 验收证据

`LF-TSK-SEC-0001` 的 `PASS` 证据至少包括：

1. 一张含扩展、API、应用层、工作进程、PostgreSQL、Redis、供应商与遥测汇入端的 data-flow/trust-boundary 图，每条穿越标明认证、校验、最小化和负责人。
2. 上述威胁登记表的逐项评审收据，至少给出预防、检测、安全降级和后续负责人；仅写“以后加安全”不算完成。
3. 滥用测试样例覆盖跨用户引用、重复事件/作业、超长/恶意字幕、格式错误供应商、陈旧结果、缓存碰撞、成本放大和遥测泄漏。
4. 密钥/data-flow 审查，证明供应商凭据只在服务端适配器，发送供应商的输入有界且无个人档案/历史/会话凭据。
5. 架构证据，证明核心模块不依赖 Chrome/YouTube、HTTP、Redis、PostgreSQL 或具体供应商，且共享存储不绕过领域合同。
