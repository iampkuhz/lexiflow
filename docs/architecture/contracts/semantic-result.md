# 语义结果合同

> Proposed。先读 [横切合同导读](README.md)。

模型输出先成为可校验的语义证据，提示编排再决定是否展示。

## 精确语义与后续证据

下面保留原合同的任务映射、必须/应当/后续条件、符合性、验收和未决假设。它们约束后续实现，不能从文档存在推断产品通过。

<!-- retained-contract:start -->
**对应任务：`LF-TSK-SEM-0002`**

本合同细化 ADR-007。语义只提供语义证据；提示编排仍独占是否展示、展示多少以及提示注释最终版本的决定权。

<a id="31-provider-neutral-结果包络"></a>

### 3.1 供应商无关结果包络

每次语义能力调用都产生一个且仅一个标准结果。包络在概念上包含以下语义元素；名称不承诺后续传输或存储字段名：

| 语义元素 | 必须约束 | 目的 |
|---|---|---|
| 能力 | 标明本次任务是消歧、语境表达、短语抽取或句子解释中的哪一类；不同能力的载荷不得互换。 | 防止供应商的通用文本响应渗入业务。 |
| 输入绑定 | 关联规范化词项/短语、内容上下文指纹和目标语言；不得只返回无法定位到输入的自由文本。 | 支持去重、缓存和陈旧结果拒绝。 |
| 结果 | 明确区分 `success`、`abstained` 与 `failure`。 | 空结果不再同时表示“不确定”“拒绝”“超时”和“格式错误”。 |
| 语义证据 | 仅在 `success` 时存在，表达能力所需的语境义、目标语言短表达或引用词段；不得携带“必须展示”一类界面指令。 | 保持模型与规则分离。 |
| 置信度 | 使用标准置信等级、来源和校准版本；供应商原生分数不能未经校准直接比较。 | 允许提示编排按一致策略消费证据。 |
| 来源证明 | 记录受控的供应商/模型系列、语义合同版本、路由策略版本与完成时间。 | 支持解释、复算和有界缓存复用。 |
| 失败分类 | `failure` 时只给标准原因与可重试提示，不把供应商原始响应当成领域错误。 | 隔离供应商 SDK 与不稳定错误格式。 |

`success` 必须通过能力专有的结构、语言、引用范围和大小校验。`abstained` 表示调用按合同完成，但系统没有足够证据给出可靠语义；它不是失败，也不能伪装成高置信空文本。`failure` 不得携带可展示语义载荷。

### 3.2 置信语义

**必须**

- 标准置信只描述“语义证据与当前有界上下文相符的可信程度”，不描述用户是否认识该词，也不直接决定提示注释是否显示。
- 置信至少支持 `high`、`medium`、`low`、`unknown` 四种可比较等级；任何数值仅在同一校准版本内有意义。
- 每个非 `unknown` 结果必须说明置信来源：供应商原生信号、确定性校验、多个候选一致性或校准器输出中的受控组合。
- 上下文缺失、引用词段无法绑定或供应商不提供可靠置信时，结果不得默认提升为 `high`。
- 提示编排必须能够拒绝低置信证据、回退到词库/快速结果，或保持无提示；不得为了完成慢速工作强制生成中文。

**应当**

- 为不同能力分开校准；消歧的置信不能直接冒充翻译自然度或短语边界置信。
- 保存足够的校准版本和结果聚合，使后续能比较“展示后点击/纠正”等效果，但不得在遥测中保存原始字幕或个人词汇档案。

**后续条件**

- 阶段 4 依据代表性语料确定数值区间、校准算法和各能力的最低可用阈值。
- 阶段 6 只可用脱敏、可追溯的学习归约证据调整阈值，不能让供应商自评替代用户行为事实。

<a id="33-malformedtimeoutrefusal-与其他失败"></a>

### 3.3 格式错误、超时、拒绝与其他失败

| 标准结果 | 判定 | 是否可作为语义成功缓存 | 调用方语义 |
|---|---|---|---|
| `malformed` | 响应无法通过结构、语言、引用边界、大小或合同版本校验。 | 否 | 本尝试失败；丢弃原始载荷。是否重路由由语义路由策略决定。 |
| `timeout` | 调用在调用方截止时间内没有得到已校验结果，包括连接、生成或读取超时。 | 否 | 本尝试终止；晚到响应不得附着到已完成尝试。持久工作可按独立重试策略继续。 |
| `refusal` | 供应商明确拒绝完成能力，或安全策略使其不返回所需语义。 | 否 | 不是空成功；可由路由策略选择其他允许的供应商，也可安全降级为无提示。 |
| `rate_limited` | 供应商表示容量/配额暂不可用。 | 否 | 作为可观测的暂时失败；不得阻塞英文优先路径。 |
| `unavailable` | 供应商、网络或适配器暂不可用且未得到业务结果。 | 否 | 按路由、重试和熔断策略处理。 |
| `budget_exhausted` | 当前任务的成本、尝试或截止时间预算已经耗尽。 | 否 | 停止该工作单元的继续消耗，保留快速/no-hint 结果。 |
| `contract_mismatch` | 供应商适配器不支持请求能力/版本，或返回版本无法归一。 | 否 | 视为配置/发布兼容问题，不做内容重试。 |
| `cancelled` | 字幕已陈旧、请求被上游取消或工作不再有用户价值。 | 否 | 停止结果发布；不把取消计为供应商内容失败。 |

**必须**

- 截止时间从应用层预算向语义端口传入；供应商适配器只能缩短，不能延长。排队等待、供应商执行和结果校验都必须计入可观察阶段。
- 单次尝试级超时/拒绝/格式错误与持久化作业的最终状态分离。一次尝试失败不自动表示作业永久失败；作业重试也不能把旧尝试改写成成功。
- 供应商输出按不可信输入处理。适配器完成结构归一和约束校验后，语义才能发布标准结果。
- 对同一工作单元的重试、兜底和并行兜底必须有总预算与去重身份，不能无界放大成本。
- 失败时客户端仍得到英文、有效快速结果或明确的无待处理任务/无增量降级；不得生成整句双语兜底。

**应当**

- 格式错误与合同不匹配进入独立告警维度，避免被笼统归入供应商超时。
- 短期失败抑制可以减少对持续故障供应商的重复调用，但必须与成功语义缓存分开，并使用短、有限的有效期。

**后续条件**

- 阶段 4 决定每个能力的截止时间、兜底顺序、尝试上限和供应商适配细节。
- 阶段 7 用压测和生产 SLO 决定熔断、舱壁隔离与回压参数。

<a id="34-acceptance-evidence"></a>

### 3.4 验收证据

`LF-TSK-SEM-0002` 只有在以下证据可复核时才可判为 `PASS`：

1. 一份供应商无关合同审查，证明四类能力都通过标准结果表达，且没有供应商 SDK 类型、自由文本响应或展示决定泄漏到提示编排。
2. 一组结构化合同测试样例，至少覆盖有效成功、合法放弃回答、低/未知置信、格式错误、超时、拒绝、速率限制、合同不匹配和迟到响应。
3. 一张状态转换表，证明尝试、持久化作业、提示注释结果三者的成功/失败不会互相冒充。
4. 一个降级旅程，证明语义的每类失败都不会延迟或替换英文字幕，且失败载荷不会成为提示注释。
5. 一份版本/置信评审记录，证明跨校准版本的数值不会直接比较，旧结果会因合同/上下文/版本不兼容而失效。

### 3.5 未决假设

| ID | 假设 | 验证时机/负责人 |
|---|---|---|
| SEM-A1 | 四类能力可共享结果包络，但需要各自载荷不变量。 | 阶段 4，语义负责人用模拟实现与至少两个供应商适配器验证。 |
| SEM-A2 | 分级置信足以驱动首版提示编排，数值校准不会成为 MVP 前置。 | 阶段 4 离线评估；若误提示率无法区分，再引入数值校准。 |
| SEM-A3 | 拒绝与格式错误的替代供应商路由收益高于额外成本。 | 阶段 4 代表性失败注入与成本测量。 |
