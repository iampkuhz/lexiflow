# 缓存正确性与隐私合同

> Proposed。先读 [横切合同导读](README.md)。

缓存命中只提高速度；有效性、归属、版本和过期仍是必要条件。

## 精确语义与后续证据

下面保留原合同的任务映射、必须/应当/后续条件、符合性、验收和未决假设。它们约束后续实现，不能从文档存在推断产品通过。

**对应任务：`LF-TSK-PRF-0002`**

缓存优化读取和复用，不改变事实负责人。个人词汇档案的权威版本、学习归约事实、持久交接和提示编排持久化结果均不能只存在于 L1 或 Redis。

### 4.1 层级与负责人

| 层/逻辑缓存 | 内容与负责人 | 是否可丢弃 | 命中前必须校验 |
|---|---|---|---|
| 扩展 L1 | 当前设备的提示注释/个人档案快照副本；客户端投递与同步定义兼容合同。 | 是 | 用户/设备归属、内容/字幕身份、提示注释修订号、档案版本、策略/合同版本、硬性过期。 |
| Redis 热点缓存 | 词库、个人档案查询、提示注释投递、语义/上下文的热点派生副本；各领域端口仍保有负责人。 | 是 | 命名空间、数据分类、负责人版本、生成版本、来源/个人档案修订号与硬性过期。 |
| PostgreSQL 持久化状态 | 学习归约事实、个人档案投影、持久工作、提示编排持久化结果。它是事实/恢复来源，不因被读穿使用就变成缓存。 | 否 | 负责人、事务状态、业务版本和授权边界。 |
| PostgreSQL 派生的复用 | 可选的语义/上下文派生结果，用于跨重启复用；仍由对应领域管理，可重建。 | 是，但删除/重建须受负责人控制 | 合同/上下文/来源/model-policy 版本、数据保留和隐私资格。 |
| 语义逻辑缓存 | 经校验的供应商无关语义证据；物理上可位于 Redis 或 PostgreSQL 派生的复用。 | 是 | 能力、规范输入、上下文指纹、目标语言、语义合同/校准/routing-compatible 版本。 |
| 上下文逻辑缓存 | 内容规范化片段和有界上下文窗口；物理上可位于 L1、Redis 或 PostgreSQL 派生的复用。 | 是 | 规范内容身份、来源修订号、片段身份/窗口、规范化版本、完整度。 |

<a id="42-key-contract"></a>

### 4.2 键合同

以下是键的语义组成，不规定字符串拼接或序列化格式。

**必须**

- 所有键都有结构定义命名空间和负责人版本；不同环境、租户隔离等级、数据类别和缓存用途不得共用可碰撞空间。
- 用户专属提示注释/个人档案键必须绑定后端确认的用户边界及档案版本。客户端提供的用户/个人档案声明不能单独决定命中。
- 语义键至少区分能力、规范化词项/短语、目标语言、上下文指纹、语义合同版本和影响语义的策略/模型系列版本。
- 上下文键至少区分规范内容身份、来源修订号、当前片段、所请求的有界窗口和规范化版本。
- 上下文/语义指纹使用规范化输入的不可逆摘要；原始字幕、整段转写、个人词汇档案或行为历史不得直接出现在缓存键、日志键或指标标签。
- 只有证明不含用户专属输入和输出的语义/上下文派生结果才可跨用户复用。只要个人档案、个人偏好或行为影响结果，就必须进入用户隔离命名空间。
- 提示注释缓存键必须覆盖语义结果版本与提示需求/规则版本；只更新语义内容但遗漏展示规则版本会导致错误复用。

**应当**

- 键构造使用稳定规范化合同，并用标准样例测试样例证明空白、大小写、Unicode、时间窗口和片段排序的确定性。
- 大对象内容只作为值；键使用稳定身份和摘要，避免 PII 暴露与超长键。
- 对相同语义/上下文未命中使用有界合并并发请求，且等待者仍遵守自己的截止时间。

**后续条件**

- 阶段 2 固定持久身份/修订号的数据语义；阶段 4 固定语义规范化；阶段 5 固定扩展 L1 的物理格式。

<a id="43-ttl-与-freshness-contract"></a>

### 4.3 存活时间与新鲜度合同

存活时间数值由真实延迟、成本和内容变化率决定，因此阶段 1 固定语义而不伪造秒数。每个缓存策略必须配置有限的软性/硬性有效期；“未配置”不得解释为永久有效。

| 层 | 软依赖过期后 | 硬性过期后 | 不受存活时间替代的失效条件 |
|---|---|---|---|
| 扩展 L1 | 可在英文优先已完成后暂用兼容旧值并异步刷新；界面必须能识别陈旧。 | 不再显示该提示注释，只保留英文并请求新结果。 | 用户切换/登出、档案版本不兼容、字幕/修订号改变、撤回/删除信号。 |
| Redis 个人档案/提示注释 | 可触发读穿刷新；旧值只有在负责人明确允许陈旧读取时可返回。 | 必须未命中并从负责人读取。 | 个人档案/提示注释版本变化、权限或数据归属变化。 |
| Redis 语义/上下文 | 可在调用预算内刷新或暂用仍兼容证据；不得延长错误/拒绝为成功。 | 必须重新计算或降级。 | 来源/上下文/规范化/合同/model-policy 版本改变。 |
| PostgreSQL 派生的复用 | 可标记待刷新，继续使用需满足负责人的兼容规则。 | 不参与新决策，并进入负责人管理的清理流程。 | 删除请求、保留策略、来源撤回、合同/隐私分类变化。 |
| PostgreSQL 事实/持久化状态 | 不使用缓存存活时间决定正确性。 | 不适用。 | 由业务保留、显式删除和状态机规则管理。 |

**必须**

- 每个入口具有可比较的生成时间、软性/硬性新鲜度界限和影响正确性的版本集合；挂钟存活时间与版本校验必须同时成立。
- 存活时间到期不是用户数据删除证明；删除、撤回和权限失效需要主动失效/清除流程。
- 失效失败时系统优先未命中/回源或不提示，不能继续展示可能跨用户或跨版本的值。
- 个人档案更新只失效用户相关提示注释/个人档案缓存，不应清空可跨用户复用的词库/语义/上下文缓存。
- 内容来源修订号、规范化版本或上下文指纹改变时，所有基于旧上下文的提示注释与语义证据均不得命中新决策。
- 缓存失败、刷新或冷启动不会丢失学习归约事实、持久工作、个人档案权威状态或提示编排持久化结果。

**应当**

- Redis 硬性过期使用受控随机抖动防止同批键同时过期；不得用无限滑动续期掩盖旧版本。
- 负向/无结果缓存只覆盖可确定复用的放弃回答/无候选语义，并使用短于成功结果的有限有效期；超时/拒绝/速率限制只允许进入独立短期失败抑制。
- 以负责人事件/版本提示做主动失效，以读取时版本检查做最终防线；任何 pub/sub 通知都不能成为唯一正确性机制。

**后续条件**

- 阶段 3/4 基准测试给出各策略个人档案的软性/硬性默认值和陈旧读取预算。
- 阶段 7 依据生产命中速率、陈旧丢弃、删除完成时延和成本调整存活时间；调整不得改变上述正确性条件。

### 4.4 隐私与最小化

**必须**

- 扩展 L1 只保存完成当前体验所需的最小派生结果，并服从登出、账号切换、权限撤回和用户清除动作；不得保存完整观看历史或整个个人词汇档案。
- Redis 不承担长期用户数据仓库；用户相关值必须隔离、有限有效并可由负责人定位清除。
- 供应商原始响应、原始模型输入、真实字幕、用户词汇状态和行为历史不得进入通用共享缓存、键、日志或测试测试样例。
- 语义跨用户复用前必须证明值不含用户或设备标识、个人个人档案影响、供应商返回的个人信息和来源访问凭据。
- 缓存观测只暴露受控层级/结果/原因/版本维度；禁止以用户、视频、字幕、词项或摘要值作为指标标签。

**应当**

- 共享派生数据与用户派生数据使用不同命名空间、访问策略和保留策略。
- 隐私清除证据同时列出 L1 通知、Redis 清除和 PostgreSQL 负责人删除；无法触达的离线 L1 依靠有限硬性过期与下次鉴权拒绝共同收敛。

**后续条件**

- 阶段 2 的 `LF-TSK-SEC-0002` 固定用户导出、删除完成语义和保留；阶段 7 验证生产清除时限。

<a id="45-acceptance-evidence"></a>

### 4.5 验收证据

`LF-TSK-PRF-0002` 的 `PASS` 证据至少包括：

1. 缓存清单，逐项标明业务负责人、物理层级、可否丢弃、用户隔离、键输入、版本、软性/硬性过期和失效来源。
2. 键标准样例测试样例，证明上下文、目标语言、个人档案/来源/规则/合同版本任一影响正确性的输入改变都会未命中；等价规范输入仍稳定命中。
3. 失效场景矩阵，覆盖个人档案更新、字幕/来源修订号、规则升级、供应商/合同升级、登出/用户切换、删除、Redis 刷新和 L1 离线。
4. 冷缓存恢复旅程，证明 Redis/L1 全空仍可从 PostgreSQL 事实/持久化结果恢复，英文渲染不受影响。
5. 隐私审查，证明键/值/遥测/测试测试样例均无真实字幕、观看历史、个人词汇档案、供应商原始输入输出或身份泄漏。
