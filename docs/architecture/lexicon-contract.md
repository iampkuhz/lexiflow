# 1. 共享词库合同

**位置：** [架构总览](overview.md) → [观看流程](flows.md) → 共享词库合同。**上游：** 离线完整来源扫描与原子发布；**下游：** Enrichment 查询已发布候选。**失败：** 冲突拒绝发布、查询未命中返回无候选，不创建观看补全任务。

Lexicon 保存可跨内容复用的英文词汇事实；不保存某次字幕采用哪个义项、用户行为或供应商载荷。准备资料、查询投影和约束见[词库持久化模型](data-model.md)。

## 1.1. 规范主词条与查询形式

`(language_tag, lemma)` 是一个来源无关的规范词条；`lexicon_entry_id` 是该组合的简短稳定身份，不把 `dataset_id` 放进业务键。每个原形、别名、屈折形在 `lexicon_hint_lookup` 有一条准确形式行。单词和固定短语都可作为主词条；一条屈折形式可以自然地对应多个主词条，不能任取第一条。`LexiconEntry` 负责离线准备阶段的词形与冲突校验；观看阶段只接收 `LexiconHintCandidate`。

一个已发布资料版本由 `lexicon_dataset.lexicon_version` 表示。Annotation 同时引用词条、义项与资料版本；旧身份不被新资料原地改写。完整重导后查询缓存按版本清空，本机显式词段抑制偏好也必须核对版本。

## 1.2. 导入期证据到最终决定

被采用来源的原始释义、记录定位、BNC/FRQ 排名、复杂词表标签和 Oxford 标记进入准备词条。BNC/FRQ 取有效正排名中较小者并换算 Zipf；与复杂标签数量按固定三角频率公式计算 0～1000 优先级。排名没有固定的“低于多少就不翻译”阈值；缺失排名只令预热优先级为零。

Oxford 标记和有效排名参与选出前 2000 个基础词，再与固定功能词合并；Oxford 原始标记不是独立的最终阻断规则。基础词、低信息短语、多义或不安全释义被准备为 BLOCK。只有单一可靠中文短释，或与来源表达核对成功的人工审定映射，才冻结为 HINT；不自动取多义列表的首项。`final_priority` 决定提示排序，`cache_priority` 独立决定预热；常见 BLOCK 可以先进入负向缓存。

## 1.3. 观看期确定性查询

字幕仅枚举连续一至三个词的准确形式；四词及以上不枚举。一个含 10 个不同 token 的句子最多生成 `10+9+8=27` 个形式，去重后缓存未命中的形式合并为**一次** PostgreSQL 批量查询；本次请求还会独立执行一次资料版本核对。全部形式已在 L1 时批量词形查询为零次，版本核对仍为一次。不分别联查准备表，也不请求模型。命中多个词条时保留全部候选，Enrichment 检查词边界、UTF-16 区间、歧义、低信息短语、重叠和每段最多三条。BLOCK 只拦截自身准确形式，不因单词被阻断就阻断包含它的完整短语。

API 查询版本与词形是两类读取；版本变化清空可重建缓存。L1 正向与负向预热分别有界；未命中不创建持久化事实或 pending 工作。

## 1.4. 来源、许可与发布

完整来源清单记录来源标识、许可、文件 SHA-256 和取得时间；原始文件按摘要受控保留供离线回查。一期不提供“每个词在每个来源的原始释义逐条数据库查询”。发布前完整扫描格式、计数与 canonical 冲突；写入在一个事务内完成，失败回滚，不保留数据库中间状态。操作入口和公式见[离线词库导入](../development/operations/lexicon-import.md)。
