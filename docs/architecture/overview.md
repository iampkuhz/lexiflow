## 1.2. 系统边界

Chrome 扩展拥有当前字幕、叠加层和本机体验状态；服务端拥有共享词库和提示规则。PostgreSQL 是服务端事实存储，Redis 与浏览器缓存均可重建。

观看请求只使用有界必要上下文，不保存观看历史，不上传本机抑制偏好。第三阶段分析材料需另行明确授权；普通字幕请求不是采集、持久化或向供应商发送文本的许可。

## 1.3. 主链路

1. 来源适配器产生 `CaptionContext`，英文独立显示。
2. Enrichment 通过 Lexicon 的公开合同读取已发布资料，以规则定位和选择提示。
3. 可靠匹配则返回提示，否则返回不提示；不调用模型、不创建当前字幕的补全工作、不返回等待模型的承诺。
4. 扩展只显示仍匹配当前字幕的结果；字幕切换、跳转或响应过期时放弃旧结果。

第三阶段在观看之外分析缺失资料，可以使用模型生成待校验材料；审核发布后由后续请求正常读取。离线流程关闭时观看链路不受影响。

## 1.4. 模块与依赖

Lexicon 与 Enrichment 是两个业务领域；`workflow` 协调用例，`:platform:adapters` 提供具体技术适配，`api` 和 `worker` 是组合根。Java 25 模块化单体不因两个进程拆成微服务；domain 不依赖框架、存储或供应商，模块不得跨域读写表。

第三阶段的分析与发布详细合同在阶段展开时设计，不为规划预建业务模块。已有模块结构见[模块边界](boundaries.md)。

## 1.5. 验证边界

词库资料能否可靠覆盖语境、来源身份能否支撑跨请求复用、优化是否有效，都需要样本和测试证明；架构文档不是交付证据。实现差距与验证结果只见[状态页](../roadmap/master-plan/status.md)。
