# 1. 架构决策

每项 ADR 固定回答**决定、取舍理由与复审条件**。产品范围见[产品说明](../product/product-brief.md)，阶段计划见[长期计划](../roadmap/master-plan.md)，执行步骤见[校验手册](../development/validation.md)。

## 1.1. ADR-001：以模块化单体交付

- **决定：** 使用 Java 25 模块化单体；`api` 与 `worker` 可独立部署，但共享领域、应用与事实存储。
- **取舍理由：** 微服务会过早引入网络一致性、部署和团队边界成本；单体以内的模块边界先控制复杂度。
- **复审条件：** 吞吐、隔离或团队所有权证据持续表明单体边界不足。

## 1.2. ADR-002：英文优先，提示可降级

- **决定：** 英文字幕本地立即显示；提示、缓存和后端可降级；观看链路不调用模型。
- **取舍理由：** 等待完整翻译会损害观看；允许空提示换取稳定主体验。
- **复审条件：** 真实时延和可用性数据表明当前预算不合理。

## 1.3. ADR-003：观看使用已发布资料，模型只用于事后分析

- **决定：** Enrichment 的共享规则使用已发布资料决定是否提示。模型仅可在第三阶段独立事后分析中补充待审核资料，不能经同步、后台补全或预取进入观看链路。
- **取舍理由：** 在线模型会增加时延和不确定性；宁可在资料不足时不提示，再经离线更新改善覆盖。
- **复审条件：** 评测表明规则无法满足质量目标且有可审计的改进依据。

## 1.4. ADR-004：最小本机学习反馈，不建设账号或同步

- **决定：** 用户可显式把词段标为“不再提示”；Chrome 扩展只在本机保存词段与词库版本的抑制偏好。产品不提供账号、多人隔离、设备注册、服务端个人档案、自动行为归约或跨设备同步。
- **取舍理由：** 显式动作能直接改善下次提示，同时避免把展示、点击或停留时间误判为熟悉度；本机存储不引入身份、同步冲突和服务端隐私运营。
- **复审条件：** 用户要求跨设备、服务端档案或自动归约，并先批准新的数据边界、删除/导出、威胁模型和迁移方案。

## 1.5. ADR-005：事后分析经发布衔接观看

- **决定：** 观看请求不创建语义工作或返回等待模型的 pending 承诺。事后分析独立运行，结果经评估、审核和版本发布供后续请求使用；失败保留已发布版本。
- **取舍理由：** 将知识更新与观看隔离，避免后台调用仍使当前字幕依赖模型；版本发布支持验证和回退。
- **复审条件：** 资料发布、撤回或恢复合同需要变化时，先确认不影响观看独立性。

## 1.6. ADR-006：基础设施合并为一个 Gradle 模块

- **决定：** 持久化、缓存、安全、观测、供应商和作业集成都放入最外层的 `:platform:adapters`，用 Java 包隔离。
- **取舍理由：** 为每种技术建立独立 Gradle 项目会制造空壳和依赖噪声；一个基础设施模块内的包边界足以表达技术隔离。
- **复审条件：** 独立发布、第三方依赖治理或团队所有权形成明确证据。

## 1.7. ADR-007：Markdown 内嵌 PlantUML 是唯一图源

- **决定：** 正文 `plantuml` 围栏是唯一图源；调试和渲染产物只存在于 `tmp/diagrams/`。
- **取舍理由：** 独立图片或 `.puml` 链接会漂移和失效；内嵌源码可随文档审阅。
- **复审条件：** IDE 正文预览或渲染合同产生可复现缺陷。

## 1.8. ADR-008：产品语言统一 Java 25

- **决定：** 产品后端使用 Java 25；Chrome 扩展使用 TypeScript；Python 只承载 Harness、Gate、生成和审计。
- **取舍理由：** 让 Python 承载产品领域会破坏统一质量边界。
- **复审条件：** 工具链兼容性或可复现性证据冲突。

## 1.9. ADR-009：知识发布与提示决策分属各自负责人

- **决定：** Lexicon 拥有可复用词库知识及版本，Enrichment 拥有 `CaptionContext` 和提示决策。离线分析不得跨域写知识；技术适配归最外层的 `:platform:adapters`，只有组合根装配实现。
- **首版范围：** 观看路径只查已发布资料。第三阶段的分析、审核及发布细节在阶段展开时确认，不预建语义服务、模型短语抽取、句子解释或动态供应商路由。
- **取舍理由：** 先保持词库与提示的稳定职责，不为事后分析提前增加领域和运行时依赖；供应商 SDK 不得进入领域。
- **复审条件：** 独立语义产品、内容生命周期或多个稳定消费者出现，并形成独立演进、发布、依赖治理或所有权证据时，再评估增加业务模块；shared kernel 也必须有具体、稳定的跨领域合同证据。
- **执行边界：** 机器边界、构建项目、任务所有权与验证合同遵循本决策的职责划分。
