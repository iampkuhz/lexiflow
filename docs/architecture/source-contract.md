# 1. 来源适配合同

**位置：** [架构总览](overview.md) → [观看时序](flows/viewing.md) → 来源适配。**输入：** YouTube 已渲染英文；**输出：** 有界字幕输入；**下一步：** [字幕身份](caption-contract.md)。**失败：** 没有可靠文本、位置或修订时只保留英文。

本页只定义 `youtube` 视频英文字幕如何成为字幕提示的输入。来源适配器负责取得并规范化字幕；它输出 Enrichment 的 `CaptionContext`，不是独立业务领域，也不参与提示决策。完整提示链路见[字幕提示流程](flows.md)，模块归属见[模块边界](boundaries.md)。

## 1.1. `youtube` 字幕处理流程

1. **取得播放上下文：** Chrome 扩展/来源适配器取得视频的稳定内容身份、字幕修订和当前位置。
2. **取得字幕：** 读取当前英文字幕片段及有限的相邻字幕；无法取得可靠英文字幕时，不伪造转写或提示。
3. **规范化与定位：** 按播放时间和片段顺序整理字幕，保留当前片段的位置，并限制单次文本与上下文窗口的大小。
4. **封装输入：** 以内容身份、来源修订、有序字幕、当前位置、有限上下文和来源专有的不透明参考组成 `CaptionContext`。
5. **交给 Enrichment：** Enrichment 根据 `CaptionContext` 和词库合同决定是否形成提示；适配器不调用模型、不决定提示，也不保存个人状态。

## 1.2. `CaptionContext` 的最小边界

| 合同内容 | 用途 | 边界 |
|---|---|---|
| 稳定视频身份与字幕修订 | 使缓存、结果和失效判断绑定同一份字幕。 | 视频或字幕切换后，旧结果必须不能匹配。 |
| 有序字幕与当前位置 | 标明正在播放的字幕片段。 | 使用规范文本、时间和顺序值，不传递 YouTube DOM 或选择器。 |
| 有限上下文窗口 | 为词义判断提供必要相邻字幕。 | 只保留任务所需范围，并限制大小。 |
| 来源专有不透明参考 | 让来源侧在需要时回到原始视频。 | Enrichment、Lexicon 和其他核心领域不可解析、导入或按其内容分支。 |

## 1.3. 浏览器 DOM 适配边界

已实现的 Chrome 来源适配器只以 YouTube 已渲染的 `.ytp-caption-segment` 文本为英文来源；
`video.currentTime` 与被动读取的 JSON3 仅用于关联可验证的轨道和时间元信息。
它把 DOM 连续变化收敛成正在显示的文本快照，以页面内不复用的片段 key 维持仍可见文字的身份；
来源暂时无法匹配时保留已有 key，本次元信息置 null，不把未知误判为换轨。仅确认的新轨道、seek
或导航构成换源边界。英文节点不被适配器修改，中文词段提示由独立覆盖层增量显示。

YouTube 渲染 DOM 不提供稳定字幕轨道标识、字幕修订或每段真实的开始/结束时间。
JSON3 事件到期与 DOM 行退出可短暂错位，因此仅可靠匹配时附加原生元信息，不伪造时间或依赖
一次 null 匹配重建字幕身份。页面内片段 key 不能声称是 `CaptionContext` 所需的规范来源修订，
也不能进入共享缓存、持久工作或异步结果投递。完整限制和体验诊断见
[Chrome 扩展本地体验与 E2E](../development/operations/extension-e2e.md)。

字幕暂时出现空帧时，增强层立即隐藏英文与中文，但在短暂窗口内保留内部片段身份；恢复时若可见文本仍连续则沿用 key，超过短暂窗口或明确换源、seek、隐藏、关闭时重置。旧行滚动封版后只保留已展示的中文，迟到响应不补写旧行；跨视觉行词组不生成提示。增强层仅在展示层临时保留离场行并平滑上移，动画结束移除，不把离场行送往后端。

## 1.4. 注意事项

- 英文字幕必须在扩展中立即显示，不能等待后端、缓存或模型。
- YouTube DOM、选择器和平台 SDK 类型只能留在来源适配器内。
- 字幕、页面标记和其他来源内容都不可信；它们只能作为数据，不能成为执行指令。
- 无法获得可靠字幕、位置或修订时，安全降级为仅英文或报告能力缺失。

## 1.5. 后续来源

网页、`pdf`、播客和其他视频平台不在本页实现范围内，暂不展开。待 `youtube` 字幕链路跑通后，再为每种来源单独确认可靠文本、位置和修订的取得方式；只有能稳定产出同一 `CaptionContext` 合同的来源才可接入。
