# 1. 运行安全

本页定义通用提示系统的缓存、信任、观测与失败边界。它不定义账号、设备、个人状态、用户隔离或跨设备清除语义，因为这些不是当前产品能力。

## 1.1. 缓存与事实

| 层 | 可保存内容 | 失效依据 |
|---|---|---|
| 扩展 L1 | 当前内容修订可用的提示结果。 | 视频/字幕切换、内容修订、结果撤回、硬性过期。 |
| Redis | 共享词库、规范上下文、语义证据与提示结果的热点派生副本。 | 负责人版本、内容修订、规则/模型版本和硬性过期。 |
| PostgreSQL | 持久工作、提示结果、必要的 `CaptionContext` 快照及其版本。 | 由 Workflow / Enrichment 的合同按保留与删除规则处理。 |

缓存只优化读取和复用，不改变事实负责人。缓存键必须包含命名空间、数据分类、内容或语义输入指纹、负责人版本和存活时间；失效规则由负责人版本和硬性过期共同限定；原始字幕、整段转写、供应商原始输入输出和密钥不得进入键、日志键或指标标签。

## 1.2. 结果失效与降级

- 内容身份、来源修订、当前片段、语义合同或提示规则版本变化时，旧提示必须未命中或被拒绝。
- 语义/上下文结果只有证明不含私人输入和来源凭据时才可作为共享缓存值。
- 失效失败时优先未命中、回源或不提示，不能继续展示不匹配当前字幕的值。
- 任何缓存、队列或模型失败只影响提示，英文字幕继续显示。

## 1.3. 信任边界

此处覆盖来自内容、客户端和供应商的滥用输入。

| 输入 | 负责人 | 最小处理 |
|---|---|---|
| YouTube 字幕与播放上下文 | 来源适配器 → Enrichment 的 `CaptionContext` 合同 | 归一、限制大小和窗口；网页标记与指令文本仅是数据。 |
| 扩展请求 | API / workflow | 校验内容引用、语言、大小、版本和幂等请求身份。 |
| 供应商结果 | Enrichment 的语义能力 + `platform:infrastructure` 实现 | 结构化校验、合同版本绑定、最小化保存。 |
| 持久工作与投递 | workflow / Enrichment | 只在持久交接确认后承诺 `pending`；结果须重验内容修订。 |

领域只能通过各自公开合同访问存储；不得利用共享数据库权限读取其他领域表。供应商凭据只存在于服务端密钥边界，不得进入扩展、持久化载荷、日志、追踪或测试样例。

## 1.4. 观测与隐私

日志和指标只使用受控运行维度，例如环境、能力、缓存层、结果类别、原因、受控供应商/模型系列和合同版本；跨流程关联使用短期、不可逆的请求关联号。不得记录原始字幕/转写、词项、中文提示、URL、密钥、供应商原始载荷或任意高基数字段。

容量和成本护栏按请求、来源、供应商和全局预算实施，不以个人账户或设备为维度。`PASS` 不能由进程存在或调用退出零推断；未运行的必要旅程必须显式为 `BLOCKED` 或 `FAIL`。

## 1.5. 后续验证

后续阶段需要验证冷缓存恢复、模型超时、迟到结果、内容修订、供应商异常、密钥泄露防护、速率限制和日志脱敏。任何未来引入账号或个人状态的提案必须先通过新的 ADR 和 OpenSpec，不能复用本页的通用缓存合同。
