# 1. 2.1.10

## 1. 两步使用

1. 在 Podman 已安装并运行的前提下，复制下方自动生成、固定镜像 digest 的 `podman run` 命令并执行；它会拉取正式镜像、创建专用命名卷并启动一个容器。等待初始化完成。
2. 下载 `lexiflow-extension-2.1.10.zip`，解压后在已安装的 Chrome 打开 `chrome://extensions`，启用开发者模式，选择“加载已解压的扩展程序”。扩展自动连接本机服务，无须填写地址或密码。

## 2. 前置条件

仅支持 macOS Apple Silicon + 已启动的 Podman，Chrome 须已安装。Podman 的安装和启动不包含在上述两步中；需要可访问 GHCR 与 GitHub 的网络，以及可用的本机端口 18080、容器名 `lexiflow-release`。命令会自动挂载 `lexiflow-release-data` 命名卷，不必预先建卷或安装 Java、Node、Python、数据库及额外脚本。

API 只绑定 `127.0.0.1:18080`，数据库不向宿主机或局域网开放。运行参数为 2 GiB 内存限额、2 CPU，不代表已证明最低资源需求；首次拉取和初始化时间受网络与主机资源影响。

## 3. 功能与修复

Java 25 API、PostgreSQL、已发布词库和首次初始化能力合为唯一运行镜像和一个容器。重启使用原命名卷，初始化完成后不重复导入；关键进程失败不会继续报告就绪，初始化中断保留恢复边界。

运行镜像的版本、源码、构建和部署身份由同一构建输入生成；只读晋升预检直接校验精确镜像归档内的配置、平台和全部身份标签，缺失、冲突或摘要变化在人工审批前拒绝，不加载镜像、不读取正式发布凭据。

Chrome 扩展显示初始化、就绪、不可用及版本不兼容状态，并核对软件、API 协议和资料身份。后端不可用时英文字幕继续显示；观看不调用模型，用户显式设置的词段抑制偏好只保存在本机。

私有候选构建与只读晋升预检自动执行，真实独立验收与审查保持完整；正式公开镜像和 GitHub Release 前只要求一次人工审批。批准后仍重核本次运行授权、精确证据与制品；旧批准不复用于重跑或后续发行。发行保护使用稳定的宿主及用户绑定，避免机器名称变化错误阻断验收，同时继续严格核对仓库、源码、候选和制品。正式晋升只复用已验收的精确制品，不重新构建；未知写入需要核实后显式恢复，不盲目覆盖或重复推送。

## 4. 下载与校验

仅提供 Chrome 扩展 ZIP、第三方对应源码包及 `release.json` 三个自定义附件；无须下载源码、主安装包或镜像 tar。运行镜像保留必要许可证告知。下方下载链接、镜像 digest、SHA-256 与启动命令由真实制品自动补充；机器应读取 `release.json`，不要解析可编辑正文作为发行身份。

## 5. 已知限制

仅有 Linux ARM64 运行镜像，不承诺其他平台或任意旧数据库版本原地迁移。数据保存在专用命名卷，不要挂载其他项目或旧版数据库卷；未知非空卷、不兼容数据和资源冲突失败关闭，不自动接管、清空或删除。完全空的同名卷允许初始化：纯 `podman run` 无法判断已有空卷归属。

本阶段不以 Chrome Web Store 上架为前提，扩展采用开发者模式加载；无账号同步或模型语境消歧。已有安装及数据需保留，更新前先核实容器名、端口、卷和回退安排。
