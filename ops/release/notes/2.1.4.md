# 1. 2.1.4

## 1. 两步使用

1. 确认下方固定 digest 的 `podman run` 命令及其资源参数；复制并运行，等待服务就绪。命令固定绑定 `ghcr.io/iampkuhz/lexiflow@sha256:...`，不使用 `latest`，会创建专用命名卷。
2. 下载 `lexiflow-extension-2.1.4.zip`，解压后在 Chrome 打开 `chrome://extensions`、启用开发者模式并加载已解压的扩展程序。

## 2. 前置

需要已安装并运行的 Podman、已安装的 Chrome，以及 macOS Apple Silicon（Linux ARM64 镜像）；本机端口 18080 必须可用。不要预创建命名卷或为容器设置应用密码。若容器名或卷已被占用，不要自动接管或删除。

## 3. 功能与修复

本版本将 API、PostgreSQL 与已发布资料整合为一个常驻容器，完整保留运行所需许可证告知和可单独下载的第三方对应源码。观看使用已发布资料，不调用模型；扩展仅访问本机服务并保留用户显式设置的本机偏好。

首次数据库初始化由持久完成协议保护中断重试，发行生命周期检查保留宿主用户目录与安全环境隔离。本版本修复晋升前候选完整性验证的跨语言请求缺项，严格绑定候选、发行清单和完整构建身份；初始化、重启、故障或完整性验收未通过时仍阻止发行。

## 4. 已知限制

仅支持 linux/arm64。容器数据保存在 `lexiflow-release-data` 命名卷中；不支持自动迁移旧版本数据库，也不要将该卷用于开发环境。未知非空卷或不兼容数据卷会失败关闭，保留原数据。完全空的同名卷会被初始化：纯 `podman run` 无法区分自动新建空卷与预先存在的空卷，不保证拒绝所有未知空卷。
