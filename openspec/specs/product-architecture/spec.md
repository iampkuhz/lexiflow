# 产品架构规范

## 1. 观看链路不使用模型

客户端 MUST 立即显示英文；所有阶段的观看链路 MUST 只消费已发布词库、规则和语义资料，MUST NOT 同步调用模型、为当前字幕创建后台模型补全或进行模型预取。

### 场景：词库或缓存缺失

- 当缺少可靠、适用的已发布资料时，返回不提示，不创建语义补全任务或 pending 承诺。
- 英文继续显示；不得以原始词典截取、多义列表或未经审核结果充当语境答案。已有经审核发布的默认首义时，按一期默认译法规则提示，不因词条多义而拒绝。

### 场景：已有资料请求晚到

- 资料查询可以异步完成，但返回前和展示前均需关联当前字幕。
- 无保留内容的字幕替换、seek、换轨或导航使旧结果失效；即使文本相同也不得绕过失效。连续追加或前缀退出时，仍完整可见的词段及其有效响应 MUST 保留并映射到新位置。

## 2. 事后分析与发布隔离

第三阶段 MAY 在独立的事后缺失分析中使用模型；模型材料 MUST 经校验、审核和版本发布才能供后续观看消费。观看请求 MUST NOT 发起、等待或订阅该分析，更新不得回补当前字幕。

### 场景：分析失败或未审核

- 模型不可用、分析停止、质量不合格或发布失败时，观看继续使用已发布资料。
- 未审核结果不能进入查询或缓存，发布需要可核对依据并支持回退。
- 路线图不构成新增字幕采集、行为上传、模型外发、个人画像或保留策略的授权。

## 3. 模块化单体与所有权

产品后端使用 Java 25。Lexicon 与 Enrichment 分别是业务 Gradle 项目，各自在 `domain` 和 `application` 包内维护领域规则与应用用例。platform adapters 隔离技术实现，`:api` 是唯一 Spring Boot 运行项目和唯一 `@SpringBootApplication`；HTTP 与未来后台任务由同一应用装配，共四个产品项目，验证和构建工具不计入产品项目。`backend/product/` 与 `backend/verification/` MUST 仅作为物理分类目录，不注册为 Gradle 项目；七个主构建项目 MUST 使用扁平项目路径，`backend/gradle/build-logic/` 保持独立 included build。Domain 不依赖 HTTP、数据库、缓存或供应商 SDK；跨模块只用公开合同，不跨域读写数据。

业务项目 MUST 按功能及职责组织模型、策略、端口与服务，MUST NOT 按 record 语法统一建目录或机械添加 DTO 后缀。Domain MUST NOT 依赖 Application；model MUST NOT 依赖服务、用例或策略实现。持久化同包私有类型 MUST NOT 为目录拆分扩大可见性。Gradle 只声明实际使用的直接依赖，ArchUnit 验证模块内及跨模块边界。

### 场景：规则查询资料

Enrichment 只从 Lexicon 的 `domain.port` 及 `domain.model` 公开合同读取已发布资料，不依赖 Lexicon 的应用层或内置词库实现，以确定性规则判断提示价值及适用性，不为决策调用模型。PostgreSQL 为事实存储，缓存与投影可重建。

## 4. 本机显式偏好

用户明确选择“不再提示”时，扩展仅在本机保存词段与词库版本的抑制偏好；不得上传、从展示/点击/停留推断熟悉度，或形成服务端个人档案、账号和同步状态。

## 5. 来源与行内展示

Chrome / YouTube 为首个客户端和来源；来源私有类型留在适配器，核心领域只接收有界的标准化字幕上下文。字幕不可靠时不伪造转写、位置或提示。

提示 MUST 以词段区间绑定英文原文，单一简短中文释义插在词段之后。仅同一提示覆盖的多词词组 MUST 以连续黄色底线标出，词间空格属于同一标记，源字幕分行仍保留。单词提示 MUST NOT 画底线；相邻独立提示 MUST NOT 合并成词组标记。显示层仅依据单个合法提示覆盖区间是否包含多个空白分隔词确定标记，不按中文长度、片段 key 数量、撇号或连字符拆词，不改变后端词条选择。词组底线 MUST 位于文本行内并有足够行距，MUST NOT 被下一行字幕背景遮挡；显式分行、自然换行及放大字号均保持可读。来源英文节点 MUST NOT 被改写；完整英文增强层即时就绪后允许可逆抑制重复绘制，不等待中文；保留源分行并允许自然换行。请求失败保留同层英文，来源失效或关闭增强立即解除抑制。仅当前页面开关 MUST NOT 持久化浏览记录或影响其他标签页。经用户明确授权，本机 API MUST 将每个成功处理的新增 `segment.key` 仅记录一次到独立的本机敏感分析日志，包含 JSON 转义的英文、词段提示覆盖与未提示区间；重试和进程重启不得重复计数，未处理或写入失败不得冒充已记录。普通 API logger 和扩展日志 MUST NOT 输出字幕原文或中文提示。经用户明确授权，零参数本机启动器 MUST 自动开启独立的敏感控制台结果流，只镜像成功新写入的片段 JSON；其他启动方式默认关闭，不回放历史、不重复计数，不向普通 logger 转发正文。控制台 MUST 明示敏感性并对换行及控制字符进行 JSON 转义。该记录只表示不可增长的片段 key 已被 API 处理，不表示源字幕消失或用户最终看见提示；不得将它标记为整屏最终渲染。分析日志不得记录观看地址、内容身份、凭据或模型载荷，不得提交、共享或作为指标标签。

## 6. 分层规划与交付

产品路线图唯一入口为 [master-plan](../../../docs/roadmap/master-plan.md)，阶段入口约束下级功能设计。方向确认不等于交付验收；未分解的产品阶段不能据路线图自动派发，不复用其他范围的历史收据。执行状态只在[状态页](../../../docs/roadmap/master-plan/status.md)维护。

### Requirement: 发布前提示资格预处理
基础词排除与完全重复释义归并 MUST 在导入预处理完成，随词库版本保存资格和来源依据。来源明确标记为 Oxford basic 的可导入独立单词 MUST 全部排除，不按排名或数量截断，缺失排名也 MUST 排除；完整短语 MUST 独立判断，不因自身或组成词的 Oxford 标记直接排除。派生行归并前保留 Oxford 单词表面证据，词条任一已归属词形命中时整体列为基础词。观看 MUST NOT 动态重算基础词名单或归并词典释义。第一阶段 MUST 支持多义词，并使用导入期按候选顺序确定并校验发布的第一义作为默认译法；真实多义本身 MUST NOT 成为排除理由。一期首义 MUST 按现有受控来源的候选顺序选择第一项；已有经来源核对的人工短释作为单候选保留。模型语义归并、重排、特征标注和结构化词义资产建设属于二期，不是一期前置条件。首项无效 MUST NOT 以第二项补位。首义 MUST 在发布前确定，观看 MUST NOT 截取原始词典列表、现场归并或调用模型排序。UNPROCESSED 资料 MUST NOT 提示。

观看 MUST 排除结构不完整或明显低信息量的短语；按已发布排名证据优先选择非基础词，未排名短语不得只因长度占用更有学习价值的提示位。提示必须非重叠，不设置固定三条上限；同区间多词条歧义时不选首条。默认短释 MUST 核对来源表达并随发布政策绑定；完整来源表达、候选顺序依据与来源引用 MUST 在受控资料中保留，不能因只展示首义而删除其他义项。首义是经验默认值，不等于上下文消歧结论或实测概率。

#### Scenario: 消费发布的基础词标记
- GIVEN 词条已在预处理阶段标记为 BASIC_VOCABULARY
- WHEN 当前字幕命中该词条或它的词形/别名
- THEN 不提示该词条，英文继续显示，完整短语独立判断

#### Scenario: 多义词显示默认首义
- GIVEN 一个非基础、符合提示价值规则的词条有多个真实义项，已发布的候选顺序依据及合法默认短释
- WHEN 当前字幕准确命中该词条且不存在不同词条身份冲突
- THEN 只展示来源候选顺序的第一项，不因多义而拒绝，不输出整个多义列表，不调用模型
- AND 完整义项保持可追溯；默认译法不符合具体上下文的风险如实记录，不宣称已消歧

#### Scenario: 多义词缺少可用默认义项
- GIVEN 默认义项未发布、为空、不合法或来源无效
- WHEN 当前字幕命中该词条
- THEN 保留英文，不临时截取来源首项或任取其他义项

## 7. 开发期最新结构

仓库 MUST 只维护最新逻辑与架构，废弃接口、配置和数据结构直接替换，不维护历史兼容分支。数据库 MUST 直接更新唯一最新结构 SQL；结构变化通过显式重建本项目开发库并完整重新导入生效，不维护递增迁移链或旧结构适配。应用启动 MUST NOT 隐式清库；重建不得影响其他项目数据。

资料的来源绑定、发布标识、完整性验证及受控发布并非旧结构兼容，MUST 保留。重建后不得复用仍被缓存或本机偏好引用的资料身份而绑定不同内容。

### 场景：阶段一的词义质量边界

第一阶段 MUST 使用已按候选顺序确定并校验发布的默认首义，MUST 拒绝未经导入校验发布的原始列表截取、未处理资料和无效来源。默认首义可能不适配具体语境；该风险及唯一字面义不适配隐喻等质量缺口不作为一期默认译法策略的阻塞，也不得宣称已经解决。上下文选择由后续词义消歧工作评估，词库知识缺口由事后资料改进处理；确定性资料校验不等于普遍语境消歧。

## 8. 增量字幕快照

观看请求 MUST 携带内容主题与轨道上下文、上次成功确认请求的冻结快照以及当前快照。每份快照按字幕组携带 windowId/startMs 与有序 segments；片段只携带 key/text/offsetMs/append/line。源窗口和时间未知时 MUST 为 null，MUST NOT 用观察时间伪造。公共合同不包含 mediaTimeMs、endMs、sequence 或 playbackEpoch，也不维护旧请求兼容分支。

插件 MUST 负责源信息关联、稳定 key、增量识别和展示；key 不因 DOM 重建或换行改变，新增文字不得增长进旧 key。append MUST 表示本次待处理内容，不是源 aAppend；成功无提示也必须确认处理覆盖。后端 MUST 只查询同组内连续新增片段，旧内容仅作边界上下文，MUST NOT 跨新旧边界补译。

新增英文 MUST 立即显示，已有提示 MUST 保留节点；纯换行不发新请求，前缀退出仅移除对应内容。单请求在途并合并最新观察，失败 MUST NOT 自动重试、确认处理覆盖或推进上次成功快照；仅在失败后的下一次有效字幕变化时，将最新快照与上次成功快照一起请求。成功无提示也确认快照；确认 MUST 绑定发送时的冻结快照，而非响应到达时的最新观察；来源隐藏或关闭增强后，迟到结果 MUST NOT 复活字幕。来源私有桥消息视为不可信输入；仅可见文字进入本机 API，字幕和观看身份 MUST NOT 写入扩展日志或持久存储。

CSS roll-up 动画改变可见行但不触发 DOM mutation 时，插件 MUST 在原生字幕动画运行期间逐帧重读可见几何，并在结束或取消时完成末次同步；MUST NOT 使用持续全页轮询或等待网络、timeupdate 才补齐英文。

同一原生裁剪窗口滚动时，插件 MUST 按窗口容量显示最新已进入的完整行，避免部分可见的首尾行同时膨胀成额外整行。连续节点中已退出的旧行 MUST NOT 因 transform 复位而重新出现；仅允许保留仍在 DOM 且正文未变、有可见交集的已展示尾行，不采集未显示的离屏新行。换源、seek、换轨、隐藏或关闭增强 MUST 重置该局部状态。叠加层 MUST 锚定裁剪窗口而非运动中文字的底部。
